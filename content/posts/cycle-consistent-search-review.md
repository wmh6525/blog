## 1. 문제: Search-R1에는 정답이 필요하다

Search-R1은 강화학습으로 검색 에이전트를 학습시키는 혁신적 방법이었지만, 한 가지 근본적 한계가 있다:

$$r(x, y) = \text{EM}(a_{\text{pred}}, a_{\text{gold}})$$

**정답(gold answer)이 반드시 필요하다.** 보상 = 정답과의 Exact Match.

이것이 문제인 이유:
- 전문 도메인(의료, 법률)에서 정답 라벨은 **비싸거나 불가능**
- 오픈엔드 질의("AI가 사회에 미치는 영향은?")에는 **정답 자체가 없음**
- 빠르게 변하는 도메인에서 정답은 **금방 낡아짐**

> **CCS의 질문**: 정답 없이도 "이 검색 궤적이 좋은지 나쁜지" 판단할 수 있지 않을까?

## 2. 핵심 아이디어: 순환 일관성 (Cycle Consistency)

### 다른 분야에서의 순환 일관성

| 분야 | 순환 |
|------|------|
| **CycleGAN** | 말 → 얼룩말 → 말 (원본 복원되면 변환 성공) |
| **비지도 기계번역** | 영어 → 불어 → 영어 (원문 복원되면 번역 성공) |
| **CCS (본 논문)** | **질문 → 검색 궤적 → 질문 복원 (복원되면 검색 성공)** |

### CCS의 가설

> **"최적의 검색 궤적은 원래 질문의 의도를 무손실 인코딩한 것이다."**

$$q \xrightarrow{\pi} \tau \xrightarrow{\phi} \hat{q} \approx q$$

- $q$: 원래 질문
- $\tau$: 검색 궤적 (검색 쿼리들 + 검색 결과들)
- $\hat{q}$: 궤적에서 복원된 질문
- $q \approx \hat{q}$이면 → 검색이 잘 된 것!

### 직관적 예시

**질문**: "부르즈 할리파를 설계한 건축가가 태어난 도시의 인구는?"

| 검색 유형 | 궤적 | 질문 복원 가능? |
|---------|------|------------|
| **적절한 검색** | 건축가 검색 → 출생지 검색 → 인구 검색 | ✅ 복원 가능 |
| **불충분한 검색** | 건축가만 찾고 멈춤 | ❌ 인구 부분 복원 불가 |
| **무관한 검색** | 구조 엔지니어를 건축가로 착각 | ❌ 잘못된 도시로 복원 |

## 3. 수학적 정의

### 상호 정보량 최대화

검색 궤적 $\tau$와 원래 질문 $q$ 사이의 **상호 정보량**을 최대화:

$$I(Q; T_\theta) = H(Q) - H(Q | T_\theta)$$

$H(Q)$는 $\theta$와 무관하므로, 이는 다음과 동치:

$$J(\theta) = \mathbb{E}_{q \sim D, \tau \sim \pi_\theta(\cdot|q)} [\log P(q | \tau)]$$

→ "검색 궤적이 주어졌을 때 원래 질문의 조건부 확률"을 최대화.

### 보상 함수

사전 학습된 고정 복원기(reconstructor) $P_\phi$로 $\hat{q}$를 생성하고, 임베딩 유사도로 보상:

$$r(\tau_i) = \text{Sim}(E(q), E(\hat{q}_i))$$

- $E(\cdot)$: 문장 임베딩 (Qwen3-Embedding-4B)
- $\text{Sim}$: 코사인 유사도
- 복원기: Gemini 2.5 Flash (고정, 학습 안 함)

### GRPO 목적 함수

$$\mathcal{L}_{\text{GRPO}}(\theta) = \mathbb{E}_{q \sim D} \left[\frac{1}{G} \sum_{i=1}^{G} \min\left(\frac{\pi_\theta(\tau_i|q)}{\pi_{\theta_{old}}(\tau_i|q)} A_i, \text{clip}(\cdot) A_i\right) - \beta D_{KL}(\pi_\theta \| \pi_{ref})\right]$$

그룹 내 상대적 이점(advantage):

$$A_i = \frac{r(\tau_i) - \mu(\lbrace r(\tau_j) \rbrace)}{\sigma(\lbrace r(\tau_j) \rbrace) + \epsilon}$$

## 4. 정보 누수 방지 — 핵심 기술적 기여

순진한 순환 일관성은 **정보 누수**에 취약하다. 복원기가 검색의 질이 아니라 **표면적 단서**로 질문을 복원할 수 있기 때문.

### 누수 경로 1: 최종 응답

```
검색 궤적: [검색1→결과1, 검색2→결과2, 최종 답변: "부르즈 할리파 건축가는..."]
                                                    ↑ 질문을 거의 그대로 반복!
```

**해결 — 최종 응답 제거** ($\psi_{\text{trace}}$):

$$\psi_{\text{trace}}(\tau) = (a_1, o_1, \ldots, a_{T-1}, o_{T-1})$$

최종 생성 $a_T$를 궤적에서 잘라냄.

### 누수 경로 2: 검색 쿼리의 엔터티

```
질의: "부르즈 할리파를 설계한 건축가가 태어난 도시의 인구는?"
검색 쿼리: "부르즈 할리파 건축가"  ← 질문의 핵심 엔터티가 그대로!
```

**해결 — NER 마스킹** ($\psi_{\text{mask}}$):

```
원본 쿼리: "부르즈 할리파 건축가"
마스킹 후: "[LOC] 건축가"        ← 엔터티를 유형 태그로 대체
```

검색 결과($o_t$)는 마스킹하지 않음. 복원기가 **검색 결과의 증거**에 의존하도록 강제.

### 전체 보틀넥 변환

$$\psi(\tau) = \psi_{\text{mask}} \circ \psi_{\text{trace}}(\tau) = (\tilde{a}_1, o_1, \ldots, \tilde{a}_{T-1}, o_{T-1})$$

NER 모델: bert-base-NER.

### 6.4 오픈엔드 심층 연구 (ResearchRubrics)

정답이 정의되지 않는 오픈엔드 과제에서 CCS의 진정한 강점이 드러난다:

| 비교 대상 | CCS 상대 개선 (Qwen2.5-7B) | CCS 상대 개선 (Qwen3-4B) |
|---------|----------------------|---------------------|
| vs Search-R1 | **+14.48%** | **+19.53%** |
| vs Search-o1 | +7.92% | +20.08% |
| vs RLIF | +17.63% | +26.81% |

**Search-R1은 정답 기반 EM으로 학습했으므로, 정답이 없는 오픈엔드 과제에서 약하다.** CCS는 정답 없이 학습하므로 오픈엔드에서 훨씬 우수.

## 7. Ablation Study

### 보틀넥 변환의 효과

| 보틀넥 구성 | 평균 |
|-----------|------|
| 전체 궤적 (쿼리 + 결과 + 최종 응답) | 0.561 |
| 최종 응답 제거 (쿼리 + 결과) | 0.545 |
| 결과만 (쿼리 제거) | 0.584 |
| **마스킹된 쿼리 + 결과 (CCS)** | **0.606** |

**분석**:
- 최종 응답 포함 시 → 0.561 (누수로 인한 잘못된 보상)
- 쿼리 마스킹 없이 → 0.545 (쿼리의 엔터티가 누수)
- 결과만 사용 → 0.584 (쿼리의 구조적 정보 손실)
- **CCS (마스킹 쿼리 + 결과)** → **0.606** (누수 차단 + 구조 보존)

마스킹된 쿼리는 단순히 누수를 막는 것 이상으로, **검색의 구조적 의도**를 보존하는 역할을 한다.

## 8. 실패 사례 분석

### 정보 공백 (Information Void)

```
질의: "문지를 작곡한 사람은?"
검색: "문지 작곡가" → "류원진"을 반환 (잘못된 동음이의어)
결과: 잘못된 정보 수집 → 질문 복원 실패 → 낮은 보상 ✅ (올바른 판단)
```

### 얕은 깊이 (Shallow Depth)

```
질의: "호바트가 속한 카운티의 인구는?"
검색: "호바트" → 도시 정보만 수집, 카운티 검색 안 함
결과: 불완전한 정보 → 질문 일부만 복원 → 중간 보상 ✅ (올바른 판단)
```

두 경우 모두 CCS 보상이 정확하게 검색 품질을 반영한다.

## 9. Search-R1 vs CCS 비교

| 항목 | Search-R1 | CCS |
|------|---------|-----|
| **보상 신호** | 정답과의 EM | **질문 복원 유사도** |
| **지도 학습 라벨** | **필수** (정답) | **불필요** |
| **보상 계산** | 문자열 비교 (즉시) | 복원기 + 임베딩 (추가 비용) |
| **오픈엔드 과제** | 약함 (정답 없으므로) | **강함** (+14-20%) |
| **클로즈드 QA** | 강함 | **동등 또는 우세** |
| **추가 모델** | 없음 | 복원기 (Gemini 2.5 Flash) |
| **RL 알고리즘** | PPO/GRPO | GRPO |
| **철학** | "정답을 맞추면 보상" | **"좋은 검색은 의도를 보존한다"** |

## 10. CCS가 의미하는 것

### RAG 학습 패러다임의 진화

```
[1세대] 프롬프팅 (학습 없음)
  └── RAG, IRCoT, ReAct

[2세대] 지도 학습
  └── Self-RAG, CRAG, RAFT

[3세대] 강화학습 + 지도 신호
  └── Search-R1 (정답 EM 보상)

★ [4세대] 강화학습 + 비지도 신호
  └── CCS (순환 일관성 보상) ← 여기
```

CCS는 **"정답 라벨이라는 마지막 지도 학습 의존성"**마저 제거했다. 이것은:
- **스케일링**: 어떤 도메인이든 질문만 있으면 학습 가능
- **오픈엔드**: 정답이 없는 과제(심층 연구, 창작)에도 적용 가능
- **비용**: 정답 어노테이션 비용 제거

## 11. 실무 시사점

### 도메인 RAG 에이전트를 만들고 싶다면

```
기존 (Search-R1):
  1. 도메인 질의 수집
  2. 각 질의에 정답 라벨링 (비용 ↑↑↑)
  3. RL 학습

CCS:
  1. 도메인 질의 수집 (라벨 불필요!)
  2. 검색 엔진 연결
  3. RL 학습 (복원기가 보상 제공)
```

특히 **정답이 명확하지 않은 도메인** (컨설팅 리서치, 시장 분석, 기술 조사)에서 CCS의 가치가 극대화된다.
