## 1. 공통 기판 — Product Key Memory

### 1.1 기본 메모리 레이어

키 $K \in \mathbb{R}^{N\times n}$, 값 $V \in \mathbb{R}^{N\times n}$은 **파라미터**다(attention처럼 활성값이 아니다). 토큰의 은닉 상태에서 쿼리 $q$를 만들고:

$$
I = \mathrm{TopK}(Kq),\qquad s = \mathrm{softmax}(K_I\, q),\qquad y = s\, V_I
$$

attention과 모양은 같지만 $N$이 수백만~수천만이다. 토큰마다 $k$개 행만 읽고, 역전파 때도 그 $k$개 행에만 그래디언트가 흐른다. **희소 조회와 희소 갱신이 구조에 내장된 레이어**라는 점이 뒤의 모든 논문의 출발점이다.

### 1.2 Product key — $N$개 키를 만들지 않고 top-k 찾기

$Kq$를 $N$개 전부 계산하면 의미가 없다. 그래서 키를 두 개의 절반 키 집합의 **데카르트 곱**으로 정의한다.

- $K^{(1)}, K^{(2)} \in \mathbb{R}^{\sqrt{N}\times n/2}$, 쿼리도 $q = [q^{(1)}; q^{(2)}]$로 반 가른다
- 각 절반에서 top-k: $I^{(1)}, I^{(2)}$ (각각 $\sqrt{N}$개만 스코어링)
- 후보 $k^2$개 쌍 $(i,j)$의 점수 $s_{i,j} = s^{(1)}_i + s^{(2)}_j$에서 다시 top-k
- 값 행 인덱스는 $(i-1)\sqrt{N} + j$

$N = 2^{20}$ (약 100만)이면 실제 스코어링은 $2 \times 1024$개뿐이다. 전체 키 행렬은 **한 번도 만들어지지 않는다**. 키가 학습 중 계속 바뀌므로 FAISS 같은 ANN 인덱스를 쓸 수 없다는 점도 product key를 쓰는 이유다.

### 1.3 이 기판이 지속학습에 매력적인 이유 (숫자로)

②의 설정 기준으로, 1M 슬롯 × 값 차원 1024의 메모리 한 층에서 토큰 하나가 건드리는 파라미터는 $k=32$행 × 1024 = **32,768개**다. 대체된 원래 FFN은 약 **5천만 개**다. 논문 표현으로는 토큰당 전체 메모리 파라미터의 "0.03%~0.0002%"만 활성화된다. MoE가 10~100개 전문가 중 1개를 쓰는 것과 비교하면 몇 자릿수 더 희소하다. He(2024)의 시각을 빌리면 **슬롯 하나가 초소형 전문가 하나인 MoE**다.

## 2. ① Memory Layers at Scale (Meta FAIR, 2024-12)

| 항목 | 내용 |
|---|---|
| 저자 | Vincent-Pierre Berges, Barlas Oğuz (주저자), Daniel Haziza, Wen-tau Yih, Luke Zettlemoyer, Gargi Ghosh |
| 코드 | [facebookresearch/memory](https://github.com/facebookresearch/memory) |
| 주장 | 메모리 증강 LM이 **2배 이상 연산의 dense 모델**, 연산·파라미터를 맞춘 **MoE**를 이긴다. 특히 사실 QA |

### 2.1 무엇을 바꿨나

Lample 2019의 PKM을 그대로 쓰되, **대규모에서 굴러가게 만드는** 공학이 기여의 대부분이다.

| 개선 | 내용 |
|---|---|
| **공유 메모리** | 여러 메모리 레이어가 **하나의 파라미터 풀**을 공유한다(Lample은 층마다 별도). 층을 늘려도 파라미터가 늘지 않는다 |
| **Memory+** | 입력 의존 게이팅 추가: $\text{out} = (y \odot \mathrm{silu}(x^\top W_1))^\top W_2$. 불안정할 때 qk-norm |
| **병렬화** | 값을 **임베딩 차원 축**으로 샤딩. 인덱스를 all-gather → 각 GPU가 자기 차원 조각만 EmbeddingBag → 자기 몫만 gather. 전체 출력을 한 GPU에 만들지 않는다 |
| **CUDA 커널** | 핵심 연산은 EmbeddingBag(top-k 행 가중합)으로, FLOPs가 아니라 **메모리 대역폭 병목**이다. 순전파 **3 TB/s** (H100 스펙 3.35, PyTorch는 400 GB/s 미만). 역전파는 atomics / row-lock / reverse-indices 세 방식. 종합 **6배** 가속 |

기본 크기는 절반 키 $2^{10}$개, 즉 **$2^{20} \approx$ 1M 슬롯**이다. 스케일링 실험에서는 4M·16M·64M까지 키운다. 64M 슬롯 × 2048차원이 약 **128B 파라미터**다. 논문에 top-k와 헤드 수는 명시되어 있지 않다(②는 같은 계열 설정으로 k=32, 4헤드를 쓴다).

### 2.2 실험 설정

- **Llama 구조**의 FFN 일부를 공유 메모리로 교체. 나머지는 동일
- 기저 크기 134M / 373M / 720M / 1.3B, **1T 토큰**. 8B는 Llama3 설정으로 200B·1T 토큰
- 비교군: dense, **MoE**(expert-choice 라우팅, 메모리보다 파라미터가 많아지는 최소 전문가 수), **PEER**(rank-1 전문가 검색, 파라미터 약간 더 많게)
- Memory+ 기본 구성: **공유 풀 하나, 메모리 레이어 3개**, 중앙 배치 stride 8(134M만 4)

### 2.5 평가

- **강점**: "FFN 대신 거대 희소 테이블"이라는 오래된 아이디어를 **1T 토큰·128B 파라미터 규모에서 실제로 돌아가게** 만들고, MoE·PEER와 공정 비교했다
- **한계(저자 인정)**: 프로덕션 효율까지는 "상당한 엔지니어링"이 남았다. 짧은 QA만 평가했고, 큰 메모리 + 작은 기저 모델은 학습이 불안정하다
- **이 묶음에서의 의미**: 결론부의 한 문장이 ②③의 씨앗이다.

> "we believe the sparse updates made possible by memory layers might have deep implications … enabling less forgetting, fewer hallucinations, and **continual learning**."

①은 지속학습 실험을 하나도 하지 않았다. 이 문장은 희망이었고, ②가 그것을 검증한다.

## 3. ② Continual Learning via Sparse Memory Finetuning (Meta FAIR, 2025-10)

| 항목 | 내용 |
|---|---|
| 저자 | Jessy Lin (Meta · UC Berkeley), Luke Zettlemoyer, Gargi Ghosh, Wen-Tau Yih, Aram Markosyan, Vincent-Pierre Berges, Barlas Oğuz |
| 헤드라인 | 새 사실 학습 후 NaturalQuestions F1 하락: **full FT 89% / LoRA 71% / SMF 11%** |

### 3.1 문제의식

> "A fundamental problem is that we optimize the **same set of parameters** across the lifetime of a model."

망각의 원인은 모든 과제가 같은 파라미터를 공유한다는 데 있다. 기존 해법은 셋이다.

- **정규화**(EWC 등): 중요한 파라미터를 덜 움직이게 하는 **페널티**
- **확장**(LoRA, 어댑터): 추가 용량이 작다. Biderman et al.(2024)의 결론대로 LoRA는 "덜 잊지만 덜 배운다"
- **리플레이**: 사전학습·사후학습·정렬을 여러 번 거친 현대 LLM에서는 무엇을 얼마나 섞을지가 점점 어렵다

SMF의 입장은 **"정규화의 아이디어를 페널티가 아니라 완전한 희소 갱신으로"** 구현한다는 것이다. 수백만 슬롯의 큰 용량이 있고, 입력마다 아주 작은 부분만 쓰니, **그 입력에 고유한 부분만** 갱신하면 된다.

### 3.2 핵심 발견 — 메모리 레이어를 그냥 파인튜닝해도 잊는다

직관적으로는 메모리 레이어가 이미 희소하니 그냥 파인튜닝하면 될 것 같다. 그렇지 않다(§6, Fig. 6). 접근된 모든 슬롯을 갱신해도 망각이 남는다. 이유는 **접근된 슬롯 중 일부가 범용**이기 때문이다. 구문 구조나 도메인의 일반적 특성을 예측하는 데 쓰이는 슬롯을 덮어쓰면 다른 입력 전반이 망가진다.

### 3.3 방법 — TF-IDF로 슬롯 고르기

문서 검색의 TF-IDF를 그대로 빌려 온다. **배치 단위**로, 슬롯 $i$의 점수는

$$
\mathrm{score}(i) = \underbrace{\frac{c(i)}{\sum_{j} c(j)}}_{\text{TF: 이 배치에서의 접근 비율}} \cdot \underbrace{\log\frac{|B|+1}{\sum_{b\in B}\mathbb{1}[c_b(i)>0]+1}}_{\text{IDF: 배경에서 얼마나 드문가}}
$$

- $c(i)$: 현재 배치에서 슬롯 $i$ 접근 횟수
- $B$: 배경 배치 집합. **DCLM 무작위 1000배치**의 접근 통계를 미리 계산해 체크포인트에 정적으로 저장한다
- 점수 상위 **top-t 슬롯의 값(value)만** 갱신한다. 순전파는 접근된 모든 슬롯을 그대로 쓰고, 나머지 슬롯의 그래디언트만 막는다

구현은 한 줄 마스크 트릭이다.

```python
mem = mem * trainable_mask + mem.detach() - (mem * trainable_mask).detach()
# trainable_mask: (memory_size, 1), top-t 행만 1
```

배치 단위로 순위를 매기므로 **과제 경계를 가정하지 않는다**. 스트리밍 설정에 그대로 쓸 수 있다.

### 3.4 옵티마이저 — SGD가 중요하다

처음에는 모든 방법에 AdamW를 썼다. SMF도 비슷한 학습량에서 덜 잊었지만, SMF만 **SGD로 바꾸자 망각이 더 줄었다**. AdamW의 파라미터별 적응 스텝·모멘텀·weight decay가 희소성과 예상치 못하게 상호작용하기 때문이다. baseline은 SGD로 바꿔도 이득이 없었다(Appendix A). 최종 설정은 **baseline은 AdamW, SMF는 SGD**다. SMF 학습률은 SGD라서 2~5 수준으로 크다.

> 이 결정은 공정성 측면에서 짚어둘 만하다. 헤드라인 숫자가 **서로 다른 옵티마이저**로 나온 것이다. 다만 Appendix Table 2가 baseline도 SGD로 돌린 결과를 보여주는데, "덜 잊지만 학습 자체가 거의 일어나지 않거나(lr ≤ 5e-5에서 TQA F1 0.36 그대로), 학습률을 올리면 똑같이 무너진다"는 모양이라 결론이 뒤집히지는 않는다.

### 3.5 실험 설정

| 항목 | 값 |
|---|---|
| 모델 | 1.3B, 22층 중 **12층 FFN → 메모리** |
| 메모리 | 1M 슬롯, k=32, 4헤드, 값 차원 1024 |
| 배치 | 64 |
| baseline | full FT(최적 lr), LoRA(전 attention·FFN 행렬, 최적 rank/α) |

**과제 1 — 사실 학습 (소량 데이터)**
- TriviaQA 테스트셋 1K 문항을 **서술문**으로 바꾸고 N개 패러프레이즈로 배치를 채운다. **스텝당 사실 하나**를 순차 학습한다
- 개인화, 한 사용자의 피드백에서 배우기 같은 좁은 데이터 상황을 가정한다
- $t = 500$이면 충분하다
- 망각 측정: **NaturalQuestions F1, GSM8K NLL**

**과제 2 — 문서 QA**
- SimpleQA 중 위키피디아 근거 문항 100개. 인용된 문서를 **1824개 청크**로 쪼개 한 청크씩 스트리밍하며 즉시 그래디언트 스텝을 밟는다
- Active Reading으로 청크당 N개 합성 증강을 만든다
- 청크당 정보량이 많아 $t = 10{,}000$

### 3.6 결과

**사실 학습**: 같은 수준의 새 지식 습득에서 NQ F1 하락이 **full FT 89%, LoRA 71%, SMF 11%**. 수치로 명시된 것은 이것뿐이고 나머지는 모두 그림이다.

**문서 QA**: 증강 데이터가 다양해 baseline도 소량 데이터 과제보다 훨씬 잘 배우지만 여전히 잊는다. SMF는 **같은 목표 성능에 훨씬 적은 망각**으로 높은·낮은 학습률 모두에서 파레토 개선한다.

**파레토 전선 (Fig. 5)**: x축은 TriviaQA F1 향상, y축은 HellaSwag 정확도 하락이다. full FT(lr 4종), LoRA(rank 3종 × α 4종 × lr 3종), SMF($t$ 25~1000 × lr 2종)를 모두 뿌리면 **SMF가 파레토 지배**한다. "더 배우면서 덜 잊는다."

### 3.7 분석 — TF-IDF가 실제로 무엇을 고르는가

| 실험 | 결과 |
|---|---|
| **TF만 (IDF 제거)** | 같은 $t$에서 비슷하게 배우지만 더 잊는다. 차이는 $t$가 작을수록(50) 커진다. $t$가 크면 둘 다 "전부"로 수렴하므로 당연하다 |
| **접근된 모든 값 갱신** | 학습량은 top-t TF-IDF와 같고, 망각은 더 크다 |
| **메모리 모델 전체 full FT** | GSM8K NLL **3.87**로 폭발한다(그림 축 밖) |
| **배경 코퍼스 = 학습셋(TriviaQA)** | 망각이 크게 증가한다. 학습 대상과 관련된 슬롯을 "흔하다"며 배제해 버리기 때문이다 |
| **배경 코퍼스 = 보존 대상(NQ)** | DCLM과 비슷하다. 일반 코퍼스로 충분하다 |

가장 흥미로운 것은 Table 1의 **핵심 집합(core set)** 분석이다. 한 사실의 모든 패러프레이즈와 질문에서 공통으로 접근되는 슬롯의 교집합은 대략 **100~500개**다. 배치당 접근되는 1k~100k개보다 훨씬 작다. TF-IDF가 고른 학습 슬롯은 **질문을 보지 않았는데도** 이 핵심 집합과 겹치고, 종종 **개체명 경계**에 정렬된다. 정답에 필요한 최소 $t$는 핵심 집합보다도 작다(예: 477개 중 25개).

> 즉 사실 하나는 수백 개 슬롯에 분산 저장되어 있고, 그중 수십 개만 고쳐도 새 사실이 들어간다. 메모리 레이어가 **지식의 주소 공간**처럼 동작한다는 가장 직접적인 증거다.

### 3.8 평가

- **강점**: 문제 정의가 선명하다(공유 파라미터 = 간섭). 해법이 단순하다(TF-IDF + 마스크 한 줄). 분석이 메커니즘까지 내려간다(핵심 집합)
- **한계**
  - 1.3B 한 규모. 기저 모델의 사전학습 데이터가 명시되지 않았다
  - **사실 학습만** 다룬다. 저자들도 인정하듯 이 영역은 RAG가 현재의 자연스러운 해법이다. 진짜 목표(코딩 에이전트가 경험에서 배우기)와의 거리가 멀다
  - 리플레이·EWC baseline이 없다
  - 본문 §5.1은 망각 지표를 "NQ F1과 HellaSwag 정확도"라 적었지만 Fig. 3은 NQ와 GSM8K다. 작은 불일치다
  - 가장 큰 전제는 **메모리 레이어를 가진 채로 사전학습된 모델**이 필요하다는 것이다. 현재 공개 모델 중 이런 것은 거의 없다. ④⑤가 이 틈을 파고든다
- 결론부의 주장은 메모리 레이어 자체가 아니라 **"희소 파라미터 갱신"이라는 원리**가 핵심일 수 있다는 것이다

## 4. ④ Improving Sparse Memory Finetuning (U. Michigan, 2026-04)

| 항목 | 내용 |
|---|---|
| 저자 | Satyam Goyal, Anirudh Kanchi, Garv Shah, Prakhar Gupta |
| 형식 | 본문 6쪽의 짧은 논문. **결과 표가 없고 모든 결과가 곡선 그림**이다 |
| 기여 주장 | (1) 기성 트랜스포머에 메모리를 이식하는 오픈소스 파이프라인 (2) TF-IDF 대신 KL 기반 슬롯 선택 (3) 안정성-가소성 검증 |

### 4.1 이식 파이프라인 (3단계)

```
Stage 1  Retrofit   Qwen-2.5-0.5B-Instruct의 층 [8, 12, 16] FFN을 버리고 메모리로 교체
                    → perplexity 급등
Stage 2  Recovery   메모리 파라미터만 OpenAssistant로 학습 ("healing")
                    → 랜덤 초기화된 메모리를 기존 residual stream에 정렬
Stage 3  Task FT    TriviaQA 1K 샘플로 full FT vs SMF(TF-IDF / KL) 비교
```

②의 가장 큰 진입장벽(메모리를 가진 사전학습 모델)을 **기성 모델 개조**로 우회하려는 시도다. 방향은 옳다.

### 4.2 KL 기반 선택 규칙

TF-IDF를 정보이론적으로 바꾼다. 배치 내 접근 분포와 배경 분포를 정의하고

$$
p_{\text{batch}}(i) = \frac{c(i)}{C},\qquad p_{\text{bg}}(i) = \frac{\mathrm{df}(i)+1}{\sum_j(\mathrm{df}(j)+1)}
$$

$D_{\mathrm{KL}}(p_{\text{batch}} \,\|\, p_{\text{bg}})$에 대한 슬롯별 기여를 점수로 쓴다.

$$
s_{\mathrm{kl}}(i) = p_{\text{batch}}(i)\,\log\frac{p_{\text{batch}}(i)+\epsilon}{p_{\text{bg}}(i)+\epsilon}
$$

TF-IDF와 구조가 거의 같다. **TF × log(1/배경빈도)** 대신 **TF × log(TF/배경빈도)**다. 차이는 배치 안에서 **많이 쓰인 슬롯에 추가 가중**이 붙는다는 점이다. 그래서 같은 슬롯을 반복적으로 고르는 경향이 생긴다(⑤가 이 점을 짚는다).

### 4.3 결과 (그림에서 읽은 근사값)

논문 본문에 수치가 없어서 아래는 **Fig. 4 곡선을 눈으로 읽은 값**이다.

| TriviaQA 학습 | TriviaQA F1 | NQ F1 (망각) | GSM8K loss (망각) |
|---|---|---|---|
| full FT | ~0.08 | ~0.003 | ~6 → **~12** |
| SMF (TF-IDF) | **~0.48** | ~0.0075 | ~2.3 → ~6.2 |
| SMF (KL) | ~0.45 | ~0.0015 | ~2.3 → ~6.2 |

SimpleQA로 바꾼 Fig. 5에서는 GSM8K loss가 full FT ~8.4→14.6, 희소 두 변형 ~3.5→4.8이다. 저자들은 TriviaQA에서는 TF-IDF가 NQ를 더 잘 보존하고 SimpleQA에서는 **KL이 필수적**이라며 "과제 의존적 트레이드오프"로 결론짓는다.

### 4.4 비판적으로 읽기

솔직히 이 논문 단독으로는 결론을 내리기 어렵다.

- **full FT baseline이 사실상 학습하지 못한다** (TriviaQA F1 ~0.08). ②에서 full FT가 사실을 잘 배우면서 잊었던 것과 대조적이다. 학습률 등 설정이 튜닝되지 않은 것으로 보이고, 하이퍼파라미터도 보고되지 않았다
- **NQ F1이 전 구간 0.02 미만**이다. 이 범위의 차이는 잡음과 구분이 안 된다. 시드도 오차막대도 없다
- 희소 변형의 GSM8K loss도 **2.3 → 6.2로 거의 3배** 오른다. full FT보다 "덜 오른다"지만 망각이 작다고 하기는 어렵다. 기저 모델 기준점도 없다
- 본문 안의 불일치: 복구 샘플 수(§3.3의 20k vs §4.1의 10k), 과제(§3.3의 HellaSwag vs 실제 TriviaQA), Fig. 5 패널 제목
- §5에서 KL을 "배경 분포에 가까이 머무르게 하는 **제약/정규화**"로 해석하는데, 방법 절의 KL은 **슬롯 순위 규칙**일 뿐 손실항이 아니다
- LoRA는 서론에서만 언급되고 실험에는 없다. "오픈소스"라면서 링크도 없다

이 논문은 **⑤의 예비 버전**으로 읽는 것이 맞다. 같은 저자들이 한 달 뒤 이 약점들을 상당 부분 보완했다.

## 5. ⑤ SMF as a Low-Forgetting Alternative to LoRA and Full Finetuning (U. Michigan, 2026-05)

| 항목 | 내용 |
|---|---|
| 저자 | Prakhar Gupta, Garv Shah, Satyam Goyal, Anirudh Kanchi (공동 1저자) |
| 게재 | **ICML 2026 1st FoGen 워크숍**. 저자 스스로 "work in progress" |
| 코드 | [prakharg55/SMF-ICML-FG](https://github.com/prakharg55/SMF-ICML-FG) |
| 헤드라인 | Additive SMF(KL)는 MedMCQA **+2.5pp**(LoRA +4.6, full FT +5.4)로 덜 배우지만, 두 망각 지표 모두 **1pp/1% 이내**로 유지 |

### 5.1 ④에서 달라진 점

| 항목 | ④ | ⑤ |
|---|---|---|
| 메모리 삽입 | 교체(replacement)만 | **교체 vs 가산(additive)** vs 가산+스칼라 학습 |
| 층 | [8, 12, 16] | {6, 12, 18}, 층별 **별도** 메모리(①과 달리 공유 안 함) |
| 목표 과제 | TriviaQA 1K | **MedMCQA 60K** (도메인 적응) |
| baseline | full FT | full FT + **LoRA** |
| 통계 | 단일 실행 | 여러 시드 평균 ± 표준편차 (시드 수는 미기재) |
| KL의 배경 분포 | df 기반 | **토큰 단위 누적 접근 횟수** 기반 |

**가산 모드**가 핵심 변경이다. 원래 MLP를 버리지 않고 그 옆에 메모리를 붙인다.

$$
h \mapsto \mathrm{MLP}_\ell(h) + \alpha \cdot \mathrm{mem}_\ell(h),\qquad \alpha_0 = 0.01
$$

### 5.2 설정

- **메모리**: $n_k = 128$ → 층당 16,384 슬롯, 값 차원 896, 4헤드, top-k 16, 키 차원 256
- **Stage 1 (dense retrofit)**: 비메모리 파라미터를 동결하고 메모리 전체를 OpenAssistant 5만 응답으로 2에폭 학습
- **Stage 2 (sparse)**: 배치마다 층당 **T = 512** 슬롯(층의 3.125%)의 값 행만 갱신. MedMCQA 6만 개, 3에폭
- 배경 통계: OpenAssistant 배치 크기 1 × 2,000개
- **LoRA**: rank 16, α 32, **모든 attention·MLP 투영**에 적용(~9M 파라미터)
- 평가(각 1,000개 hold-out): MedMCQA 정확도(목표) / **WikiText-103 PPL**, **TriviaQA 정확도**(망각)

### 5.3 결과 — Table 1

| 방법 | MedMCQA ↑ | WikiText PPL ↓ | TriviaQA ↑ |
|---|---|---|---|
| Base Qwen | 0.344 | 13.146 | 0.256 |
| 교체 SMF (KL) | 0.354 | 16.577 | 0.179 |
| 교체 SMF (TF-IDF) | 0.355 | 16.501 | 0.207 |
| **가산 SMF (KL)** | **0.369** | **12.723** | **0.252** |
| 가산 SMF (TF-IDF) | 0.346 | 12.773 | 0.255 |
| 가산+S SMF (KL) | 0.378 | 13.139 | 0.223 |
| 가산+S SMF (TF-IDF) | 0.369 | 13.456 | 0.245 |
| LoRA | 0.390 | 15.470 | 0.193 |
| Full FT | **0.398** | 18.907 | 0.163 |

base 대비 변화로 다시 쓰면:

| 방법 | 학습 (MedMCQA) | PPL 변화 | TriviaQA 변화 |
|---|---|---|---|
| 교체 SMF | +1.0~1.1pp | **+26%** | −5~8pp |
| **가산 SMF (KL)** | **+2.5pp** | **−3.2% (오히려 개선)** | **−0.4pp** |
| 가산+S SMF (KL) | +3.4pp | ≈0 | −3.3pp |
| LoRA | +4.6pp | +17.7% | −6.3pp |
| Full FT | +5.4pp | +43.8% | −9.3pp |

읽을 거리 셋.

1. **교체는 지배당한다.** 원래 MLP를 버리면 학습도 적고 망각도 크다. 0.5B 규모에서 사전학습된 MLP 경로를 없애는 것 자체가 파괴적이다. ②의 "메모리를 가진 채 사전학습된 모델"이라는 전제가 괜히 있던 게 아니다. ④의 교체 방식 결과를 소급해서 의심하게 만드는 결과이기도 하다
2. **가산 SMF(KL)는 파레토 전선 위의 다른 점이다.** LoRA보다 2.1pp 덜 배우는 대신 PPL은 오히려 나아지고 TriviaQA는 시드 편차 이내다. **"LoRA보다 낫다"가 아니라 "LoRA와 다른 트레이드오프 지점"**이라는 것이 정확한 요약이다
3. **가산 TF-IDF는 거의 배우지 않는다**(+0.2pp). 논문은 이 행을 따로 언급하지 않는다. 가산+S로 스칼라 $\alpha$를 풀어줘야 TF-IDF도 +2.5pp가 된다

### 5.4 KL vs TF-IDF

패턴은 이렇다. **KL은 PPL을 더 잘 지키고, TF-IDF는 TriviaQA를 더 잘 지킨다.** 가산+S에서 TF-IDF→KL로 바꾸면 MedMCQA +0.9pp, TriviaQA −2.2pp다.

저자들의 가설("plausible"로 표현): KL은 배치 내 빈도에 로그 가중을 더 주므로 **같은 고빈도 슬롯을 계속 고른다**. 그 슬롯이 사실 지식도 담고 있으면 반복 갱신으로 망가진다. TF-IDF는 선택이 더 분산된다. → 어떤 망각을 더 중시하느냐에 따라 규칙을 고르라는 결론이다.

### 5.5 비용 — SMF가 LoRA보다 "작지" 않다

| 방법 | 저장 파라미터 | 추론 모델 크기 변화 | Stage 2 스텝당 갱신 |
|---|---|---|---|
| Full FT | 0 추가 | 0 | ~494M |
| LoRA | ~9M | **0 (병합 시)** | ~9M |
| 교체 메모리 | ~52M | +13M (+2.6%) | ~1.38M |
| 가산 메모리 | ~52M | **+52M (+10.5%)** | ~1.38M |

**스텝당 갱신량**만 작고 저장·추론 비용은 LoRA보다 크다. 게다가 Stage 1 retrofit과 배경 통계 수집이라는 **선행 비용**이 붙는다. wall-clock이나 GPU 메모리 측정은 없다.

### 5.6 평가

- **강점**: ④의 약점(baseline 부실, 단일 실행, 교체만)을 거의 다 고쳤다. "SMF가 이긴다"고 과장하지 않고 **트레이드오프 지점**으로 정직하게 위치시킨다. 파라미터 회계표도 유용하다
- **한계(저자 인정)**
  - 0.5B 모델 하나, 도메인 하나(의료 MCQ), 평가 1,000개 슬라이스
  - 망각 지표 두 개뿐이다. 지시 따르기·코드·다단계 추론은 측정하지 않았다
  - **업데이트 국소성의 효과를 dense retrofit 단계와 분리하지 못했다.** Stage 1에서 OpenAssistant로 52M 파라미터를 dense 학습한 것 자체가 PPL 개선(13.15→12.72)의 원인일 수 있다. "Stage 1만 하고 Stage 2는 안 한" 행이 표에 있어야 했다
  - LoRA를 모든 투영에 걸었다. attention만 걸었거나 rank를 낮췄다면 LoRA도 덜 잊었을 수 있고, 저자들도 이를 인정한다
- **추가로 짚을 점**: $T$, 메모리 크기, 층 위치, top-k, LoRA rank에 대한 ablation이 없다. ②의 Fig. 5처럼 하이퍼파라미터를 훑어 **전선 전체**를 비교해야 "다른 지점"인지 "더 나은 전선"인지 판별할 수 있다

## 6. ③ Fast-weight Product Key Memory (Sakana AI, 2026-01)

| 항목 | 내용 |
|---|---|
| 저자 | Tianyu Zhao, Llion Jones |
| 코드 | [SakanaAI/fast-weight-product-key-memory](https://github.com/SakanaAI/fast-weight-product-key-memory) |
| 헤드라인 | 4K로 학습한 ~112M 활성 파라미터 모델이 **128K NIAH에서 70~84%**(4회 반복 읽기 기준). "Sparse Test-Time Training" |

### 6.1 동기 — TTT/Titans의 병목은 dense함

선형 attention, Mamba2, DeltaNet은 이력을 고정 크기 상태로 압축하므로 용량이 제한된다. **TTT, Titans**는 상태 행렬 대신 빠른 가중치 MLP를 두고 재구성 손실로 즉석 갱신한다. 하지만 MLP는 **dense**하다. 긴 문맥을 담을 만큼 키우면 매번 갱신·조회하는 비용이 파라미터 수에 비례해 커진다.

PKM은 약 $10^6$개 슬롯을 두고 약 $2\times10^3$개만 스코어링한다. **거대한 용량 + 희소한 갱신**이라는 점에서 빠른 가중치의 이상적인 그릇이다.

저자들의 프레이밍이 이 묶음 전체를 정리해 준다.

> 느린 가중치(PKM) = **의미 기억** — 데이터셋 전반의 사실
> 빠른 가중치(FwPKM) = **에피소드 기억** — 현재 문맥에 특화된 결합

그리고 관련 연구에서 ②를 직접 언급한다. **SMF는 의미 기억을 갱신하고, FwPKM은 에피소드 기억을 갱신한다.**

### 6.2 무엇이 빠르고 무엇이 느린가

| 구분 | 파라미터 | 언제, 무엇으로 갱신 |
|---|---|---|
| **빠른 가중치** $\theta$ | 값 $V \in \mathbb{R}^{N\times d_v}$, 절반 키 $K^{(1)}, K^{(2)}$ | 학습·**추론 모두**, 국소 손실로 |
| **느린 가중치** $\phi$ | $q, v$, 게이트, 출력용 RMSNorm·Linear | 학습 때만, 전역 LM 손실로 |

### 6.3 순전파

$$
q_t = \mathrm{Lin}^q_\phi(\mathrm{RMS}(h_t)),\quad v_t = \mathrm{Lin}^v_\phi(\mathrm{RMS}(h_t)),\quad g_t = \sigma(\mathrm{Lin}^g_\phi(\mathrm{RMS}(h_t)))
$$

$$
\hat v_t = \mathrm{PKM}(q_t;\theta),\qquad o_t = g_t\,\hat v_t + (1-g_t)\,v_t
$$

$v_t$는 **"이 토큰에 대해 메모리가 기억해야 할 값"**이라는 목표이자 게이트가 닫힐 때의 우회로다.

### 6.4 쓰기 규칙 — 청크 단위 명시적 덮어쓰기

인과성을 위해 크기 $C = 512$의 **청크**로 처리하고, 청크를 다 읽은 **뒤에** 빠른 가중치를 갱신한다. 청크 안의 예측은 이전 청크까지 갱신된 메모리만 쓴다.

**값 갱신 (기억하기)**:

$$
\mathcal{L}_{\text{mem}} = \sum_{t=1}^{C} \tfrac12\, g_t\, \|v_t - \hat v_t\|_2^2
$$

- $\frac12$ MSE의 $\hat v$에 대한 그래디언트는 $-(v-\hat v)$다. 단위 스텝이면 예측이 정확히 목표로 **덮어써진다**. 명시적 메모리 재기록이다
- 한 청크에서 같은 행을 여러 토큰이 읽었으면 평균낸다: $\nabla^{\text{agg}}_{V_i} = \frac{1}{N_i^{\text{read}}}\nabla_{V_i}\mathcal{L}_{\text{mem}}$ ("경쟁하는 쓰기의 합의")
- $V_i \leftarrow V_i - \nabla^{\text{agg}}_{V_i}$. **학습률이 없다**(사실상 1). 그래서 손실을 평균이 아니라 **합**으로 둔다
- 게이트 $g_t$가 출력 혼합과 **쓰기 강도**를 동시에 결정한다. 메모리에 많이 의존하는 토큰이 많이 쓴다

**키 갱신 (주소 붕괴 막기)**:

$$
\bar p^{m} = \frac1C\sum_t s'^{m}_t,\qquad \mathcal{L}_{\text{addr}} = -H(\bar p^{1}) - H(\bar p^{2})
$$

청크 전체의 **주변 슬롯 사용 분포의 엔트로피를 최대화**한다. 개별 쿼리는 뾰족해도 되고, 평균적으로 슬롯을 고르게 쓰게 만든다.

### 6.5 작동하게 만든 실전 선택들

| 선택 | 내용 | 중요도 (ablation) |
|---|---|---|
| **Lookahead 목표** | $q_t$를 **다음 토큰**의 값 $v_{t+1}$과 짝지어 저장. 국소 목표를 다음 토큰 예측에 정렬 | **절대적**. 제거하면 NIAH 4K 80.8 → **8.2** |
| **게이트 가중 손실** | $\mathcal{L}_{\text{mem}}$의 $g_t$ | 제거하면 128K NIAH 74.8 → 19.4 |
| **주소 손실** | 엔트로피 최대화 | 제거하면 128K 74.8 → 32.2, 슬롯 커버리지 28%→8% |
| **IDW 스코어** | 내적 대신 $-\log(\epsilon + \|q-K_i\|^2)$. 키가 노름을 키워 점수를 올리는 것을 막고 **군집 중심(prototype)**처럼 동작하게 한다 | 내적 쓰면 붕괴·발산해서 ablation에서 제외 |
| 목표 정규화, 빠른 가중치 그래디언트 클리핑 없음, FP32 | 수치 안정성 | 소폭 |

### 6.6 실험 설정

- 12층, Qwen3-Next 원칙(Gated DeltaNet + gated softmax attention 교차), **~112M** 파라미터
- 백본 4종: GDN / GDN+SWA(3:1) / GDN+FA(3:1) / FA
- 메모리는 2, 6, 10층. PKM은 MLP를 **대체**, FwPKM은 토큰 믹서 **앞에 삽입**
- 둘 다 $512^2$ = 262,144 슬롯. PKM은 4헤드×Top-32, FwPKM은 1헤드×Top-8
- LongContext64 5B + FineWeb-Edu 5B = **10B 토큰**, 시퀀스 4K, H100×4

### 6.9 평가

- **강점**: 희소 메모리를 빠른 가중치로 쓴다는 발상이 깔끔하고, dense 빠른 가중치(FwMLP, LaCT)와의 대비가 명확하다. ablation과 슬롯 통계(충돌률·커버리지)까지 성실하다. 게이트 해석은 설계 직관을 준다

  - Titans와의 직접 비교가 없다
  - **보존을 못 한다.** 저자들도 공고화(consolidation) 메커니즘이 필요하다고 인정한다

## 7. 종합 — 같은 기판, 두 개의 시간 척도

### 7.1 거울상인 두 갈래

| | ② SMF 계열 (②④⑤) | ③ FwPKM |
|---|---|---|
| 갱신 시점 | 파인튜닝(오프라인) | **추론 중**(온라인) |
| 갱신 대상 | 값 $V$의 top-t 행 | 값 $V$(재구성) + 키 $K$(엔트로피) |
| 슬롯 선택 | TF-IDF / KL, **배경 대비 특이한** 슬롯 | top-k로 읽은 슬롯 전부, 게이트 가중 |
| 옵티마이저 | SGD, lr 2~5 | 학습률 없는 단위 스텝(명시적 덮어쓰기) |
| 기억 종류 | **의미 기억** | **에피소드 기억** |
| 잘하는 것 | 보존 (NQ 망각 11%) | 빠른 습득 (128K NIAH) |
| 못하는 것 | 적게 배움 (LoRA 대비 −2pp) | **보존 불가** (다음 도메인에 덮임) |

이 표는 신경과학의 **상보적 학습 시스템(CLS) 이론**과 거의 그대로 겹친다. 해마는 빠르게 배우고 간섭에 약하며, 신피질은 느리게 배우고 안정적이다. 둘 사이를 **공고화**가 잇는다. 이 묶음에는 그 공고화에 해당하는 논문이 아직 없다. [해마 구현 서베이](../hippocampal-memory-attention-survey/)에서 "대부분의 시스템이 빠뜨리는 것"으로 꼽았던 바로 그 자리다.

자연스러운 다음 실험은 이렇다. **FwPKM이 추론 중 적어둔 슬롯을, SMF의 TF-IDF 선택으로 느린 PKM에 옮겨 적는다.** 두 메모리가 같은 product-key 구조라 인터페이스가 맞는다. ③의 저자들도 결론에서 크기가 다른 FwPKM과 Titans류 메모리를 섞는 계층 구조를 언급한다.

### 7.2 다섯 편에서 확인된 것

1. **희소 조회만으로는 부족하고, 무엇을 갱신할지 골라야 한다.** ②의 "접근된 값 전부 갱신"은 잊는다. 슬롯 중 일부는 구문·일반 예측용 범용 슬롯이다. ③도 주소 손실 없이는 슬롯이 몇 개에 몰려 붕괴한다. 두 갈래 모두 **슬롯 사용 분포 관리**가 핵심 부품이다
2. **옵티마이저가 희소성과 상호작용한다.** ②에서는 AdamW → SGD가 망각을 줄였고, ③은 학습률 없는 단위 스텝을 쓴다. 적응형 옵티마이저의 모멘텀·per-parameter 스케일은 "딱 이 행만 고친다"는 의도를 흐린다
3. **메모리를 가진 채 사전학습되어야 한다.** ⑤에서 기존 MLP를 메모리로 **교체**하면 PPL이 26% 오르고 지배당했다. **가산**해야 쓸 만하다. 메모리 레이어가 널리 퍼지려면 ①처럼 처음부터 넣고 사전학습한 공개 모델이 필요하다
4. **메모리는 사실에 강하고 절차에는 약하다.** ①의 8B에서 MBPP가 오히려 떨어졌다. ②의 결론도 "사실 학습만 검증했다"다. 코드·추론 능력의 지속학습에 이 기판이 맞는지는 아직 증거가 없다
5. **커널이 병목이다.** ①은 순방향 EmbeddingBag에 6배 가속을 들였고, ③은 희소 쓰기 커널이 없어 2.5~3배 느리다. 이론 FLOPs의 이득이 wall-clock으로 이어지지 않는다

### 7.3 아직 답이 없는 질문

| 질문 | 현재 상태 |
|---|---|
| 규모가 커져도 SMF의 파레토 우위가 유지되나? | 1.3B(②), 0.5B(⑤)가 전부 |
| LoRA 쪽 전선 전체와 비교하면? | ⑤는 LoRA 한 설정만. ②는 전선 비교를 했지만 옵티마이저가 달랐다 |
| 사실 이외(코드, 스타일, 추론)도 슬롯에 들어가나? | 증거 없음. ①의 MBPP 후퇴는 부정적 신호 |
| 리플레이·EWC와 비교하면? | 다섯 편 모두 없음 |
| 빠른 메모리 → 느린 메모리 공고화 | 제안만 있음 (③ 결론, 7.1) |
| 수많은 사용자가 각자 슬롯을 갖는 개인화는? | ②가 동기로 들지만 실험은 없음. 슬롯 충돌·격리 문제가 열려 있다 |
