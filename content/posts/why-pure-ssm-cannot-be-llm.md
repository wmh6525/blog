## 처음 읽는 분을 위한 안내

**학습 위치:** [문장을 읽으며 기억하는 모델]({{< relref "learn" >}}#memory) · 9/13

요약 메모로 전체 분위기는 알 수 있어도 오래전 문장의 특정 값을 정확히 찾아야 하면 다른 정보가 필요할 수 있다. 이 글은 압축한 상태로 처리하는 방식의 요구와 한계를 다룬다. 제목의 결론보다 각 과제의 조건과 근거를 따로 읽는 것이 좋다.

**먼저 알아둘 말**

- [상태·SSM]({{< relref "ai-glossary" >}}#state): 상태는 이전까지 읽은 정보를 다음 단계에 전달하는 내부 값이다. SSM은 이 상태가 입력에 따라 바뀌고 출력을 만드는 관계를 모델링한다.
- [압축·병목]({{< relref "ai-glossary" >}}#compression): 정보를 더 작은 표현에 담는 일. 저장량과 계산량을 줄일 수 있지만 어떤 정보가 남는지도 확인해야 한다.
- [Attention]({{< relref "ai-glossary" >}}#attention): 현재 계산에 필요한 다른 위치의 정보를 가중치를 주어 섞는 장치. 가중치가 크다는 사실만으로 판단의 원인을 확정할 수는 없다.

**이번 글의 목표:** 요약 기억과 정확한 과거 조회가 다른 요구임을 이해하기.

토큰과 벡터가 낯설다면 [텍스트 데이터 다루기]({{< relref "posts/build-llm-ch2-working-with-text-data" >}})의 설명부터 읽자.

**본문에서 먼저 볼 순서:** **1. 근본적 한계: 고정 크기 상태의 정보 손실** → **2. 근본적 한계: 콘텐츠 기반 랜덤 접근 불가** → **3. 근본적 한계: 계산 표현력 한계**.

## 요약

Mamba(Selective SSM)는 선형 시간 복잡도와 상수 메모리 추론이라는 매력적인 특성을 가지지만 **순수 SSM만으로는 완전한 LLM이 될 수 없다**. 이는 단순한 스케일 문제가 아니라 **정보 이론적, 계산 이론적 한계**에서 비롯된다.

핵심 결론: SSM은 시퀀스 처리의 ~90%를 효율적으로 담당할 수 있지만 나머지 ~10% — 정확한 리콜, ICL, 특정 형식 계산 — 에는 어텐션이 필수적이다. 이것이 **Nemotron-H가 ~8% 어텐션 레이어만 사용하면서도 반드시 포함하는 이유**이다.

## 1. 근본적 한계: 고정 크기 상태의 정보 손실

### 문제

SSM은 전체 히스토리를 **고정 크기 상태 벡터** $h(t) \in \mathbb{R}^N$으로 압축한다. 이 과정은 본질적으로 **손실 압축(lossy compression)**에 해당한다.

| 모델 | 메모리 | 과거 접근 |
|------|-------|---------|
| Transformer (Attention) | $O(L)$ — KV 캐시가 문맥에 비례 | 모든 과거 토큰에 **무손실** 접근 |
| SSM (Mamba) | $O(1)$ — 고정 크기 상태 | **압축된** 요약만 접근 |

HiPPO의 이론적 근사 오차 한계:

$$\lVert f - f^{(t)} \rVert \leq \frac{C}{N^s}$$

$N$차 상태로는 과거 함수의 $s$번 미분 가능한 성분까지만 근사 가능하다. 자연 언어처럼 **이산적이고 불규칙한** 시퀀스에서는 이 한계가 심각해진다.

### 직관적 예시

10,000 토큰 문맥에서 "3번째 문단의 첫 단어가 뭐였지?"라는 질문을 생각하자.

- **Transformer**: KV 캐시에서 해당 위치를 직접 조회 → 정확한 답
- **SSM**: 10,000 토큰을 128차원 상태로 압축했으므로 → 해당 단어의 정보가 이미 사라졌을 가능성이 높음

> **이것은 모델 크기나 학습 데이터를 아무리 늘려도 해결되지 않는다.** 고정 크기 상태의 정보 용량은 상태 차원 $N$에 의해 결정되며, $N$을 키우면 효율성이라는 SSM의 핵심 장점이 사라진다.

압축된 상태는 과거 정보 가운데 무엇을 남길지 선택한 결과다. 전체 문맥의 경향을 활용하는 작업과 특정 위치의 값을 정확히 다시 찾는 작업은 이 압축에 서로 다른 요구를 한다. 아래 한계들은 각 과제에서 필요한 정보와 상태 표현의 관계를 따져 보는 것이다. 뒤의 하이브리드 구조는 압축된 기억과 직접 조회 경로를 함께 쓰는 설계로 읽으면 된다.

## 2. 근본적 한계: 콘텐츠 기반 랜덤 접근 불가

### 문제

Attention의 핵심 능력: **"이 쿼리와 관련된 과거 토큰은 어디에 있는가?"**를 전체 문맥에서 검색할 수 있다.

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}}\right) V$$

이것은 **콘텐츠 기반 랜덤 접근(content-based random access)** — 쿼리 $Q$와 모든 키 $K$를 비교하여 관련 값 $V$를 검색한다.

SSM은 이 능력이 **원리적으로 불가능**하다:

$$h_t = \bar{A}_t h_{t-1} + \bar{B}_t x_t$$

상태 업데이트는 **순차적이고 비가역적**이다. 특정 과거 토큰을 "찾아서" 접근하는 메커니즘이 존재하지 않는다.

### H3 논문의 진단 (ICLR 2023)

H3는 SSM이 언어 모델링에서 부족한 **두 가지 구체적 능력**을 식별했다:

1. **이전 토큰 리콜(Recall)**: 과거에 본 특정 토큰을 정확히 기억하고 재생하는 능력
2. **토큰 간 비교(Comparison)**: 현재 토큰과 과거 토큰을 비교하는 능력

이 두 능력 모두 **전체 문맥에 대한 접근**이 필요하다.

### Based 논문의 발견 (ICML 2024)

Based는 **상태 크기 vs 리콜 능력**의 근본적 트레이드오프를 식별했다:

- 상태가 작으면: throughput ↑, 리콜 ↓
- 상태가 크면: throughput ↓, 리콜 ↑

짧은 슬라이딩 윈도우 어텐션(window=64)을 추가하자 리콜이 **+6.22%p** 개선되었고 throughput은 FlashAttention-2의 24배를 유지했다.

> **극소량의 어텐션이 리콜 능력을 극적으로 개선한다** — 이것이 하이브리드의 핵심 동기이다.

## 3. 근본적 한계: 계산 표현력 한계

### 형식적 증명들

| 결과 | 증명 내용 | 저자 |
|------|---------|------|
| Parity 불가 | 실수 대각 SSM은 $\sum x_i \bmod 2$를 계산 불가 — 회전 동역학이 필요 | Sarrof, Veitsman, Hahn (2024) |
| FSA 시뮬레이션 불가 | 유한 상태 선형 재귀는 일부 유한 오토마타를 시뮬레이션 불가 | Merrill & Sabharwal (2023) |
| TC$^0$ 미만 | SSM은 Transformer가 계산 가능한 TC$^0$ 클래스의 **진부분집합**만 계산 가능 | Merrill et al. (2024) |
| 연관 리콜 한계 | $K$개 키-값 쌍 중 하나를 검색하려면 상태 $\geq K$ 필요 | 정보 이론적 논증 |

### Parity 문제: 가장 단순한 반례

입력 비트열 $x_1, x_2, \ldots, x_n$에서 $\sum x_i \bmod 2$를 계산하는 과제:

| 모델 | 정확도 |
|------|------|
| Mamba-2 (실수 상태) | ~50% (무작위 추측) |
| Mamba-3 (복소수 SSM) | ~100% |

Mamba-3가 복소수 상태(회전 행렬)로 parity를 해결했지만 이것은 **하나의 특정 실패 모드**를 수정한 것이지 **계산 표현력 클래스 자체를 바꾼 것이 아니다**.

### 계산 클래스 계층

```
Turing Machine (무제한)
    ⊃
Transformer (TC^0 — 임계 회로)
    ⊃
SSM / Linear RNN (AC^0 이하)
    ⊃
고정 컨볼루션 (LTI SSM)
```

**SSM이 계산할 수 있는 함수의 집합은 Transformer가 계산할 수 있는 함수의 집합보다 엄격히 작다** — 이것은 모델 크기와 무관한 **구조적 한계**이다.

## 4. 근본적 한계: In-Context Learning (ICL) 제약

### 문제

ICL = 문맥에 제시된 예시로부터 새로운 입출력 매핑을 학습하는 능력.

```
입력: "dog→개, cat→고양이, bird→"
출력: "새"
```

이 과제는 **현재 입력("bird")을 문맥의 모든 예시와 비교**해야 한다. 이것은 본질적으로 all-pairs 연산이며, $O(L^2)$ attention이 자연스럽게 지원하지만 $O(L)$ SSM은 지원하지 못한다.

### Grazzi et al. (2025)의 실험 결과

| ICL 유형 | SSM | Transformer |
|---------|-----|-------------|
| **통계적 ICL** (분포 학습) | 가능 | 가능 |
| **정확한 ICL** (정확한 함수 학습) | **불가** | 가능 |
| **정확한 토큰 검색** (문맥에서 특정 토큰 찾기) | **불가** | 가능 |

SSM은 "대략적인 패턴"은 학습할 수 있지만, "정확한 매핑"은 학습할 수 없다.

## 5. Falcon Mamba: 순수 SSM의 한계를 보여주는 실험적 증거

Falcon Mamba (TII, 2024) — **어텐션 없는 순수 Mamba 7B**, 5.8T 토큰 학습.

### 성공한 곳

| 벤치마크 | 결과 |
|---------|------|
| 일반 언어 모델링 (perplexity) | Mistral 7B, Llama-3.1 8B 능가 |
| 상식 추론 (ARC, HellaSwag) | 경쟁적 |
| 일반 지식 (MMLU) | 경쟁적 |

### 실패한 곳

| 과제 | 원인 |
|------|------|
| 긴 프롬프트에서 정확한 정보 검색 | 고정 크기 상태의 정보 손실 |
| Needle-in-haystack | 콘텐츠 기반 랜덤 접근 불가 |
| 다단계 추론 (이전 결론 재접근) | 중간 결과가 상태에서 소실 |
| 정확한 ICL | 예시-입력 비교 불가 |

> **핵심**: 데이터를 5.8T 토큰까지 늘려도 구조적 한계는 해결되지 않았다. 이것은 **스케일 문제가 아니라 아키텍처 문제**이다.

## 6. 공학적 한계: Mamba-3 등에서 해결된 것들

모든 한계가 근본적인 것은 아니다. 일부는 **공학적으로 해결 가능**하다:

| 한계 | 해결책 | 모델 |
|------|-------|------|
| 실수 고유값의 회전 불가 | 복소수 SSM (데이터 의존 RoPE) | Mamba-3 |
| 이산화 정확도 | Exponential-Trapezoidal (2차 정확도) | Mamba-3 |
| 디코딩 하드웨어 활용률 | MIMO (FLOPs 4배, latency 동일) | Mamba-3 |
| 학습 속도 | SSD chunk-wise 알고리즘 | Mamba-2 |
| Attention sink 현상 | 학습 가능 Meta Tokens | Hymba |

이것들은 SSM을 **더 좋은 SSM**으로 만들지만 근본적 한계(정보 손실, 랜덤 접근 불가, 계산 클래스)를 해결하지는 못한다.

## 7. 하이브리드가 답인 이유

### 경험적 증거: ~8% 어텐션이면 충분하다

| 모델 | 규모 | SSM:Attention 비율 | 결과 |
|------|------|-------------------|------|
| Mamba-2-Hybrid (NVIDIA) | 8B | ~85:15 | Transformer 12개 벤치마크 전부 능가 (+2.65%p) |
| Hymba (NVIDIA) | 1.5B | ~80:20 (헤드 수준) | 2배 큰 Llama-3.2-3B 능가, 캐시 20% |
| Nemotron-H (NVIDIA) | 56B | **~92:8** | Llama-3.1-70B 동등 + **3배 빠른 추론** |
| Jamba (AI21) | 52B (MoE) | 레이어 교차 | 256K 컨텍스트, 단일 80GB GPU |

### 왜 8%인가?

Nemotron-H의 `hybrid_override_pattern`을 분석하면:

```
M-M-M-M*-M-M-M-M-M*-M-M-M-M-M*-...
(M=Mamba, *=Attention, -=MLP)
```

어텐션 레이어는 ~10레이어마다 1개씩 **균등하게 분산**되어 있다. 이것은 "정보 체크포인트" 역할을 한다:

- SSM 레이어가 시퀀스를 효율적으로 처리하면서 상태를 점진적으로 손실
- 주기적 어텐션 레이어가 전체 문맥을 다시 스캔하여 **손실된 정보를 복원**
- ~8% 미만이면 리콜/ICL 성능이 눈에 띄게 저하
- ~8% 이상이면 효율성 이점이 급감

### 하이브리드의 Pareto 최적

```
성능
  ↑
  |        ★ 하이브리드 (Nemotron-H)
  |    ○ Transformer
  |
  |  △ 순수 SSM (Falcon Mamba)
  |
  └──────────────→ 추론 효율성
```

하이브리드는 Transformer의 성능과 SSM의 효율성을 **동시에** 달성하는 유일한 지점이다.

## 8. 근본 vs 공학 한계 정리

| 분류 | 한계 | 해결 가능? |
|------|------|----------|
| **근본** | 고정 크기 상태의 정보 손실 | 불가 (상태를 키우면 효율성 상실) |
| **근본** | 콘텐츠 기반 랜덤 접근 불가 | 불가 (SSM 구조의 본질적 제약) |
| **근본** | 계산 표현력 클래스 한계 (TC$^0$ 미만) | 불가 (크기 무관한 구조적 한계) |
| **근본** | 정확한 ICL 불가 | 불가 (all-pairs 비교 필요) |
| 공학 | 실수 고유값 회전 불가 | Mamba-3 복소수 SSM |
| 공학 | 이산화 정확도 | Mamba-3 Exp-Trapezoidal |
| 공학 | 하드웨어 활용률 | Mamba-3 MIMO |
| 공학 | 학습 속도 | Mamba-2 SSD |

---

## 9. 결론: SSM의 역할은 "대체"가 아니라 "보완"

순수 SSM이 Transformer를 완전히 대체할 수 없는 이유는 **단순히 아직 좋지 않아서가 아니라, 원리적으로 불가능한 계산이 존재하기 때문**이다.

그러나 SSM의 가치는 여전히 크다:

1. **시퀀스 처리의 ~90%는 SSM으로 충분하다** — 문맥 압축, 패턴 인식, 순차적 처리
2. **나머지 ~10%만 어텐션이 필요하다** — 정확한 리콜, ICL, 콘텐츠 기반 검색
3. **이 ~10%를 ~8%의 어텐션 레이어로 해결**하면, 3배 빠른 추론 + 동등 이상의 성능

Nemotron-H가 56B 규모에서 Llama-3.1-70B와 동등한 정확도를 3배 빠른 추론으로 달성한 것은, 이 "보완적 결합"이 현재 시점에서 **최적해**임을 보여준다.

> **"SSM vs Attention" 경쟁의 답은 이미 나왔다: 둘 다 쓰되, SSM을 주축으로 하고 어텐션을 최소한으로 결합하라.**
