## 1. 문제: 기존 RAG는 "언제, 무엇을 검색할지" 모른다

### 기존 접근법의 한계

| 접근법 | 문제 |
|--------|------|
| **Standard RAG** | 고정된 1회 검색 → 복잡한 질의에 부족 |
| **Self-RAG** | 반성 토큰을 **지도 학습**으로 주입 → 라벨 데이터 필요 |
| **CRAG** | **외부 평가기** 별도 학습 필요 |
| **IRCoT / ReAct** | 프롬프팅 기반 → LLM의 기존 능력에 의존, 학습 없음 |

> **Search-R1의 질문**: 지도 학습 라벨 없이, **결과만 보고** LLM이 스스로 검색 전략을 학습할 수 있지 않을까?

---

## 2. 핵심 아이디어: DeepSeek-R1 + 검색 엔진

**DeepSeek-R1**이 증명한 것: RL로 **결과 보상만** 주면 LLM이 스스로 추론, 자기검증, 자기수정을 학습한다.

**Search-R1이 확장한 것**: 같은 원리를 **검색 엔진 호출**까지 적용.

```
DeepSeek-R1:   질의 → [추론... 추론... 추론...] → 정답
Search-R1:     질의 → [추론... 검색! ... 추론... 검색! ... 추론...] → 정답
                              ↑ LLM이 스스로 학습               ↑ 정답 여부만 보상
```

## 3. 상호작용 형식: 특수 토큰 6개

| 토큰 쌍 | 역할 | 생성 주체 |
|---------|------|---------|
| `<think>` ... `</think>` | 내부 추론 | LLM |
| `<search>` ... `</search>` | 검색 쿼리 | LLM |
| `<information>` ... `</information>` | 검색 결과 | **시스템** (검색 엔진) |
| `<answer>` ... `</answer>` | 최종 답변 | LLM |

### 실제 상호작용 예시

```
<think> "Curious" 향수와 관련된 정보를 찾아야 한다 </think>
<search> Curious fragrance information </search>
<information> Doc 1: Curious는 Britney Spears의 향수 브랜드로... </information>
<think> Britney Spears의 향수이군. 그녀의 출생지를 찾아보자 </think>
<search> Britney Spears birthplace </search>
<information> Doc 1: Britney Spears는 미시시피주 McComb에서... </information>
<think> McComb, Mississippi가 답이다 </think>
<answer> McComb, Mississippi </answer>
```

**LLM이 스스로 결정하는 것**: 언제 `<search>`를 호출할지, 어떤 쿼리를 작성할지, 언제 `<answer>`로 종료할지.

## 4. RL 학습 프레임워크

### 4.1 목적 함수

표준 RL:

$$\max_{\pi_\theta} \mathbb{E}_{x \sim D, y \sim \pi_\theta(\cdot|x)} [r_\phi(x, y)] - \beta \cdot D_{KL}[\pi_\theta \| \pi_{ref}]$$

Search-R1 확장 — 검색 엔진 $R$과의 상호작용 포함:

$$\max_{\pi_\theta} \mathbb{E}_{x \sim D, y \sim \pi_\theta(\cdot|x; R)} [r_\phi(x, y)] - \beta \cdot D_{KL}[\pi_\theta(\cdot|x; R) \| \pi_{ref}(\cdot|x; R)]$$

궤적 $y$에는 LLM이 생성한 토큰과 검색 엔진이 반환한 토큰이 **모두 포함**.

### 4.2 보상 함수: 놀랍도록 단순

$$r_\phi(x, y) = \text{EM}(a_{pred}, a_{gold})$$

**이진 Exact Match** — 정답이면 1, 아니면 0. 그게 전부.

- 형식 보상 없음
- 과정 보상 없음
- 신경망 보상 모델 없음
- 검색 품질 보상 없음

**결과만 보고 모든 것을 학습한다.**

### 4.3 핵심 기술: 검색 토큰 손실 마스킹

궤적에는 LLM이 생성한 토큰과 검색 엔진이 반환한 토큰이 섞여 있다. 검색 결과 토큰에 대해 정책 그래디언트를 계산하면 안 된다 — LLM이 생성한 것이 아니므로.

$$J(\theta) = \mathbb{E}\left[\frac{1}{\sum I(y_t)} \sum_{t: I(y_t)=1} \min(\text{ratio} \cdot A_t, \text{clip}(\text{ratio}) \cdot A_t)\right]$$

$$I(y_t) = \begin{cases} 1 & \text{LLM이 생성한 토큰} \\ 0 & \text{검색 엔진이 반환한 토큰} \end{cases}$$

`<information>...</information>` 블록의 토큰은 그래디언트에서 **제외**.

### 마스킹 효과

| 구성 | 평균 정확도 (7B) |
|------|-------------|
| 마스킹 없이 | 0.343 |
| **마스킹 적용** | **0.431 (+25.7%)** |

### 4.4 PPO vs GRPO

| | PPO | GRPO |
|--|-----|------|
| 비평(critic) 모델 | 필요 | **불필요** |
| 수렴 속도 | 느림 | **빠름** |
| 안정성 | **안정** | 보상 붕괴 위험 |
| 최종 성능 (7B) | **0.431** | 0.350 |

PPO가 더 안정적이고 최종 성능이 높다.

## 5. 롤아웃 알고리즘

```
입력: 질의 x, 최대 검색 횟수 B
출력: 전체 궤적 y

1. 초기화: y = [], 검색 횟수 b = 0
2. WHILE b < B:
   a. LLM이 토큰 생성 (</search>, </answer>, <eos> 중 하나까지)
   b. IF <search> 감지:
        쿼리 추출 → 검색 엔진 호출 R(q)
        결과를 <information>...</information>으로 삽입
        b += 1
   c. IF <answer> 감지:
        최종 답변 추출 → 반환
   d. IF 잘못된 액션:
        "이전 액션이 유효하지 않습니다..." 메시지 삽입 → 재시도
3. 반환: 전체 궤적 y
```

## 8. 창발적 행동 (Emergent Behavior)

### 8.1 자기검증 (Self-Verification)

RL 학습 중 모델이 **자발적으로** 다음 행동을 보인다:

```
<think> 충분한 정보를 모은 것 같다. 하지만 확인해보자 </think>
<search> [이미 알고 있는 내용을 재검증하는 쿼리] </search>
<information> [확인 결과] </information>
<think> 맞다. 확신을 가지고 답하겠다 </think>
<answer> ... </answer>
```

이것은 DeepSeek-R1에서 관찰된 자기검증 행동의 **검색 증강 버전**이다.

### 8.2 점진적 검색 증가

학습 초기 (0-100 스텝): 응답 길이 감소 (불필요한 토큰 제거, 과제 구조 적응)

학습 후기 (100-500 스텝): 응답 길이 **증가** — 검색 호출 빈도가 올라가면서 검색 결과가 응답에 포함

→ 모델이 **학습이 진행될수록 더 많이 검색**하는 행동을 학습.

## 9. 다른 접근법과의 핵심 차이

| | 학습 방식 | 검색 라벨 | LLM 수정 | 검색 전략 |
|--|---------|---------|---------|---------|
| **RAG** | 없음 | 불필요 | 없음 | 고정 1회 |
| **Self-RAG** | **SFT** (반성 토큰) | **필요** | **필수** | 학습된 판단 |
| **CRAG** | SFT (T5 평가기) | **필요** | 없음 | 3단계 분류 |
| **IRCoT** | 없음 (프롬프팅) | 불필요 | 없음 | 프롬프트 의존 |
| **Search-R1** | **RL** (결과 보상만) | **불필요** | 없음 | **자율 학습** |

**Search-R1만의 독보적 장점**: 지도 학습 라벨이 **전혀 필요 없다**. 정답 여부만 보상으로 주면 모든 검색 행동이 RL에서 창발한다.

## 10. 성공/실패 사례 분석

### 성공: 멀티홉 분해

**질의**: "Chris Jericho와 Gary Barlow의 공통 직업은?"

```
<search> Chris Jericho career </search>     → 프로레슬러이자 뮤지션
<search> Gary Barlow career </search>       → 가수, 작곡가
<search> Chris Jericho musician </search>   → 밴드 Fozzy 보컬
<think> 둘 다 뮤지션! </think>
<answer> musician </answer>  ✅
```

4번의 검색으로 복잡한 비교 질의를 분해하여 정답 도출.

### 실패: 복잡한 질의 미분해

**질의**: 복잡한 멀티홉 질의를 **통째로** 검색 엔진에 전달 → 관련 없는 결과 → 오답

모델이 질의를 하위 질문으로 **분해하지 못하는 경우** 실패.

## 13. 실무 시사점

### RAG 시스템 구축 시 Search-R1이 의미하는 것

```
기존:  검색기 설계 → 프롬프트 설계 → LLM 연결 (수동 파이프라인)

Search-R1 패러다임:
  1. 검색 엔진(API) 준비
  2. 학습 데이터: (질의, 정답) 쌍만 필요 (검색 라벨 불필요!)
  3. RL 학습 (8× H100, 500 스텝)
  4. 모델이 스스로 최적의 검색 전략을 학습
```

**가장 큰 장점**: 도메인별로 "언제 검색해야 하는지", "어떤 쿼리를 써야 하는지"를 **수동으로 설계할 필요가 없다**. 정답만 주면 모델이 알아서 학습한다.

## 14. 한계

1. **검색 엔진 품질 의존**: 검색 엔진이 좋지 않으면 학습 효과 제한
2. **계산 비용**: 8× H100 GPU 필요 (PPO + 롤아웃 + 검색 서버)
3. **검색 횟수 제한**: 최대 4회로 제한 — 극히 복잡한 질의에 부족할 수 있음
4. **복잡한 질의 분해 실패**: 멀티홉 질의를 하위 질문으로 나누지 못하는 경우 존재
5. **도메인 외 일반화**: NQ+HotpotQA로 학습 → 다른 도메인으로의 전이 미검증

## 15. RAG 학습 방법론 계보에서의 위치

```
프롬프팅 기반 (학습 없음)
  ├── RAG (고정 1회 검색)
  ├── IRCoT (교차 추론+검색, 프롬프트)
  └── ReAct (추론+행동, 프롬프트)

지도 학습 기반
  ├── Self-RAG (반성 토큰 SFT)
  ├── CRAG (T5 평가기 SFT)
  └── RAFT (문서 읽기 SFT)

★ 강화학습 기반 (라벨 불필요)
  └── Search-R1 (결과 보상만으로 검색 전략 학습) ← 여기
```

Search-R1은 RAG의 **"검색 전략을 사람이 설계"하는 패러다임**에서 **"모델이 스스로 학습"하는 패러다임**으로의 전환을 보여준다.
