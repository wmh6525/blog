## 1. 한 줄 요약

> **"AI가 AI 개발을 돕는가"가 아니라, "개선 루프 자체가 시스템 안으로 들어왔는가, 그리고 그 루프에 대한 권한이 얼마나 내생화되었는가"를 묻는다.**

기존 서베이들이 *무엇이 바뀌는가*(모델·프롬프트·도구·워크플로)로 분류했다면, 이 논문은 **개선에 관한 의사결정 중 어느 것을 AI가 가져갔는가**로 분류한다. 같은 컴포넌트를 갱신하더라도 결정 권한의 소재가 다르면 다른 레벨이다.

RSI는 "이 조율 작업의 일부가 개선 대상 시스템 자신의 지속적 능력이 될 수 있는가"를 묻는다.

## 3. ★ 핵심 기여 1 — Headroom-Closed Index (HCI)

### 3.1 왜 만들었나

벤치마크마다 측정하는 양이 달라 원시 점수를 그냥 합칠 수 없다. 논문은 **2023년~2026년 9월** 사이 공개된 모델에 대해 **10개 능력 영역, 393개 모델–벤치마크 관측**을 수집하고 정규화한다.

### 3.2 정의

먼저 같은 프로토콜 계열(benchmark version + evaluation harness가 안정적이거나 교량 가능한 경우)끼리만 묶고, 여러 출처가 같은 조건으로 보고하면 가중 합의 점수를 낸다.

$$\bar{s}_{mbh} = \frac{\sum_i \tilde{w}_i\, s_{imbh}}{\sum_i \tilde{w}_i}$$

가중치는 **벤치마크 소유자 표 3 / 독립 공통 하네스 평가 2.5 / 벤치마크·모델 합동 보고 2 / 모델 제작자 표 1**이고, **자체 보고값에는 추가로 0.75를 곱한다.** 자기보고 편향을 눌러둔 장치다.

그 다음 **HCI**로 정규화한다.

$$H_{mbh} = 100 \times \frac{\bar{s}_{mbh} - F_{b,0}}{100 - F_{b,0}}$$

여기서 $F_{b,0}$는 해당 벤치마크가 데이터셋에 **처음 들어온 해의 90퍼센타일 모델 점수**다.

```
  HCI = 0    →  그 벤치마크 도입 연도의 프런티어
  HCI = 100  →  만점
```

영역 궤적은 벤치마크 계열별 90퍼센타일 프런티어를 모델 수의 제곱근으로 가중 평균한다.

$$T_{d,y} = \frac{\sum_{b \in B_{d,y}} \sqrt{n_{b,y}}\, Q_{b,y}}{\sum_{b \in B_{d,y}} \sqrt{n_{b,y}}}$$

제곱근 가중은 커버리지가 좋은 계열에 더 실어주되 가장 큰 표가 지배하지 못하게 하는 장치다.

**엄밀성 하나**: 최신 모델 감사에서 고려한 33개 결과 중 **17개만 채택**했다. Terminal-Bench·DeepSWE·CyberGym·ExploitBench·AutomationBench·BrowseComp에서 온 나머지 16개는 벤치마크 버전이나 평가 설정을 기존 계열에 연결할 수 없어 **참고용으로만 보존**하고 궤적에서 제외했다. 이 블로그의 [LLM Harness 최적화·오류](../llm-harness-optimization-errors/)에서 다룬 프로토콜 비교가능성 문제를 정면으로 처리한 것이다.

### 3.3 결과 — 세 가지 관찰

#### 관찰 1. 프런티어 상승의 크기와 시점이 영역마다 다르다

**2026년 HCI**:

| 영역 | HCI |
|---|---:|
| 고등 수학 | **86.4** |
| 대학원 수준 과학 | **85.8** |
| 광범위 지식 | 77.2 |
| 법률 추론 | 64.5 |
| 멀티모달 추론 | 62.2 |
| 프런티어 학술 폭 | 60.4 |

연간 증분 $\Delta T_{d,y}$이 드러내는 패턴이 서로 다르다.

```
 광범위 지식 :  +32.8  →  +26.9  →  +17.6     둔화
 법률 추론   :  +48.2  →  +11.4  →   +4.9     급격한 둔화
 고등 수학   :          +32.8  →  +53.6       ★ 가속
 멀티모달    :          +59.7  →   +2.5       ★ 급정지
```

> 단일 집계 벤치마크 하나였다면 **수준과 궤적 모양의 이 차이가 전부 가려졌을 것이다.**

#### 관찰 2. ★ 대화형 능력에 격차가 남아 있다

이것이 논문 전체의 논증을 떠받치는 관찰이다.

| 영역 | 2026 HCI | 대학원 과학(85.8) 대비 |
|---|---:|---:|
| 사이버보안 에이전트 | 91.9 † | +6.1 |
| 검색·터미널 에이전트 | 56.8 | **−29.1** |
| 소프트웨어 공학 | 52.6 | **−33.2** |
| **도구 에이전트** | **39.9** | **−45.9** |

<sub>† 후기 Cybench 관측은 과제 부분집합이나 pass@1 집계가 바뀌어 논문이 점선으로 표시하고 주의를 요구한다.</sub>

- 도구 에이전트는 2026년에 **8.2 → 39.9**로 급상승했지만 여전히 최하위
- 소프트웨어 공학은 2025년 +40.8, 2026년 +11.9로 둔화
- 사이버보안과 도구 에이전트의 차이가 **52.0포인트**

> **경계가 명확하거나 검증이 쉬운 환경에서의 이득이 길고 상태를 가진 워크플로로 균일하게 전이되지 않았다.**

논문은 이를 자율성 레벨과 연결한다 — 경계가 명확한 평가는 주로 **L1~L2**를 시험하고, 환경 과제는 **L2~L3**를, 대화형 워크플로는 **L3~L4**의 검증·메모리·적응 요구를 노출한다.

#### 관찰 3. ⚠️ 남은 헤드룸 — 이것은 예측이 아니다

논문은 RSI가 격차가 큰 영역에 우선적으로 작용할 수 있다는 **가설을 예시**하는 식을 제시한다.

$$R_d = 100 - 0.22\,(100 - T_{d,2026})$$

| 영역 | 2026 | 예시 종점 |
|---|---:|---:|
| 사이버보안 | 91.9 | 98.2 |
| 검색·터미널 | 56.8 | 90.5 |
| 소프트웨어 공학 | 52.6 | 89.6 |
| 도구 에이전트 | 39.9 | 86.8 |

**여기서 주의해야 한다.** 논문 자신이 이를 *illustrative*(예시적)라고 반복해 표시한다. 계수 0.22에는 경험적 근거가 없고, 그림의 post-2026 영역은 빗금으로 처리되어 있다. 그런데 이런 그림은 **예측으로 오독되기 쉽다.** 이 수치를 인용할 때는 "논문의 가설을 시각화한 것"이라는 단서를 반드시 함께 옮겨야 한다.

## 4. RSI의 정의와 개선 루프 해부

### 4.1 분석 단위를 알고리즘이 아니라 루프로

논문의 방법론적 선택이다.

> 자동화된 최적화가 곧 자기개선인 것은 아니고, 지속적 학습이 곧 학습 과정에 대한 자율성인 것은 아니며, **AI가 외부 산출물을 개선했다고 해서 그 AI 시스템 자체가 바뀐 것은 아니다.**

### 4.2 개선 루프의 9개 구성요소

| 구성요소 | 정의 |
|---|---|
| **AI system** | 개선 주기를 가로질러 능력 상태가 추적되는 계산 주체 전체 |
| **System state** | 한 라운드 끝에 보존되어 **다음 라운드가 물려받는 것** |
| **Experience** | 이후 수정에 쓰이는, 이전 상호작용에서 얻은 정보 |
| **Target** | 이번 라운드에서 직접 수정되는 대상 |
| **Improver** | 상태 + 경험 → 후보 수정으로 변환하는 기제 |
| **Strategy** | improver가 어디를 탐색하고 어떻게 후보를 생성할지 정하는 방법. **보존되면 나중 개선의 target이 될 수 있다** |
| **Verifier** | 후보를 평가하고 수용 규칙을 적용하는 기제 |
| **Improvement** | 수용 규칙을 통과해 **보존되고 다음 상태에 들어간** 수정 |
| **Successor** | 수용된 개선을 물려받아 갱신된 상태로 다음 라운드에 들어가는 AI 시스템 |

여기서 서베이 전체를 관통하는 **세 가지 질문**이 나온다.

```
① 루프는 어디서 닫히는가?      →  겉보기 개선이 실제로 시스템으로 돌아오는가
② 무엇이 갱신·상속되는가?      →  개선의 지속적 운반체는 무엇인가
③ 어떤 결정이 외부에 남는가?   →  개선 과정에 대한 권한이 얼마나 이전되었는가
```

### 4.3 RSI 정의

> 지능 시스템이 과제·환경·다른 지능 에이전트와의 지속적 상호작용을 통해, 획득한 경험과 피드백을 **자율적으로 자기 자신에 대한 지속적 변화로 전환**하고(모델 파라미터, 에이전트 하네스, 개선 정책 등), **그 변화가 이후의 자기개선을 생성·평가·선택·통합하는 기제에 다시 영향을 줄 수 있는** 능력.

목표는 (1) 능력 프런티어 확장, (2) 자원 효율 증가, (3) 인간이 규정한 전략을 넘어선 새로운 해 발견의 셋이다.

### 4.4 이웃 패러다임과의 구분

| 특성 | 지속학습 | AutoML | 에이전틱 AI/ML | **RSI** |
|---|:---:|:---:|:---:|:---:|
| 라운드 간 학습 | ✓ | ◦ | ◦ | ✓ |
| 지속적 보존 | ✓ | ◦ | ◦ | ✓ |
| 시스템 자기수정 | ✓ | ◦ | ✗ | ✓ |
| 후보 제안 | ✗ | ✓ | ✓ | ✓ |
| 갱신 검증 | ◦ | ✓ | ◦ | ✓ |
| **후속자 재진입** | ✓ | ✗ | ✗ | ✓ |
| **기제 수정** | ✗ | ◦ | ✗ | ✓ |
| **기제 재사용** | ✗ | ✗ | ◦ | ✓ |

<sub>✓ 핵심 목표 · ◦ 부차적 지원 · ✗ 범위 밖</sub>

아래 세 행이 RSI를 가르는 지점이다. **기제 자체가 수정되고 재사용되는가.**

## 5. ★ 핵심 기여 2 — 자율성 5단계

### 5.1 계층

```
 B0  In-Task 개선
     출력만 바뀌고 ★지속적 시스템 변화 없음★ — RSI 아님 (기준선)
       │  경계: 지속성(persistence)
       ▼
 L1  개선 실행 자율성
     인간이 무엇을·어떻게·성공 기준까지 정함. AI는 실행
     예) FineWeb-Edu — 인간이 정의한 교육 품질 라벨을 적용하되 기준 자체는 선택하지 않음
     예) Meta Capacity Efficiency — 엔지니어 디버깅 전문성을 재사용 가능한 수리 스킬로 인코딩
       │  경계: 전략 선택권 이전
       ▼
 L2  개선 전략 자율성
     목표·과제 경계·평가 기준은 외부 고정. ★어떻게 개선할지는 AI가 진단·결정★
     예) Self-Harness — 실행 트레이스로 하네스 수정을 제안·검증 (벤치마크·승격 규칙은 고정)
       │  경계: 학습 의제에 대한 통제
       ▼
 L3  학습 신호·경험 획득 자율성
     ★다음에 무엇으로부터 배울지★ 를 학습자 상태에 따라 결정
     예) SIMA 2 — 현재 행동 평가로 약점을 겨냥한 후속 연습 과제 생성
       │  경계: 배포 환경으로의 확장
       ▼
 L4  환경 적응 자율성
     배포 상호작용으로 지속 상태를 개정. 수용·거버넌스 규칙은 외부
     예) PANDO — 장기 상호작용 중 재사용 규칙을 관측 결과에 따라 승인/강등
       │  경계: ★재귀적 상속★
       ▼
 L5  재귀적 상속 자율성
     이후 개선을 지배하는 ★기제 자체★ (improver·verifier·연구 정책)를 지속적으로 개정
     예) A-Evolve-Training — 개발 점수가 외부 이득을 예측하지 못하자 연구 정책을 개정해
         다음 학습 라운드를 지휘
```

### 5.2 레벨 간 경계의 압축 서술

논문 §3.7이 이를 한 문단으로 정리한다.

| 전이 | 무엇이 추가되는가 |
|---|---|
| B0 → L1 | **지속성** — 수용된 변화가 현재 과제를 넘어 살아남아야 한다 |
| L1 → L2 | **전략 선택** — 규정된 것을 실행하는 대신 어떤 개입을 시도할지 AI가 결정 |
| L2 → L3 | **미래 학습 의제** — 진화하는 학습자가 다음에 획득할 경험에 영향 |
| L3 → L4 | **배포·환경 상호작용**으로 확장, 변화하는 운영 조건에서도 유용해야 함 |
| L4 → L5 | **재귀적 상속** — 이후 개선을 책임지는 기제가 상속되는 개선 대상이 됨 |

### 5.3 ⚠️ 높은 레벨이 더 나은 것은 아니다

논문이 명시적으로 경고한다.

> **더 높은 자율성 레벨이 그 자체로 더 나은 개선 과정을 의미하지는 않는다.** 위임된 권한이 커지는 것은 비효율적 탐색, 신뢰할 수 없는 피드백, 퇴행, 평가자 악용, 낮은 전이와 공존할 수 있다.

따라서 **AI가 내생화한 개선 책임의 범위**와 **결과적 개선의 질·효율**을 분리해서 봐야 한다. 증거 분포는 이렇다.

```
  L1~L2  ████████████████████  비교적 폭넓은 시스템이 뒷받침
  L3~L4  ████████             도메인 의존적
  L5     ██                   경계가 제한된 프로토타입과 초기 산업 시스템에 집중
```

## 6. ★★ 구조적 L5 vs 효과적 L5 — 이 논문의 가장 날카로운 구분

기존 서베이와의 차별점 중 가장 중요한 것이다.

| | 정의 | 입증 난이도 |
|---|---|---|
| **구조적 재귀** (structural) | 개정된 개선 기제가 **상속되어 이후 라운드를 지배**함을 보임 | 상대적으로 쉬움 |
| **효과적 재귀** (effective) | 그 개정된 기제가 **비교 가능한 예산과 독립 평가 아래 더 나은 후속자를 산출·선택**함을 보임 | **매우 어려움** |

> 높은 과제 성능만으로는 개선 기제가 개정·보존·재사용되었음을 보이지 못한다.

논문이 드는 분별 예시가 명쾌하다.

```
  자기수정 과제 코드가 있어도 → 이후 개정을 책임지는 과정이 그대로면 증거 불충분
  과제 에이전트 코드가 그대로여도 → 후속자 평가자가 진화했다면 구조적 L5 성립
```

**그리고 효과적 L5의 증거는 사실상 없다.** 논문이 직접 인정한다.

> AIDE2 실험은 진화한 하네스를 외부 improver로 설치했을 때 **통계적으로 유의한 효율 이점을 확립하지 못했다.** 이것은 실질적인 경험적 공백으로 남아 있다.

## 7. RSI를 의심하게 만드는 세 가지 — 반증 사례들

논문의 미덕은 실패를 숨기지 않는다는 점이다. §1.3의 세 문제와 근거 수치를 그대로 옮긴다.

### 7.1 안전한 상속 (Safe inheritance)

지속성이 곧 지속적 이득은 아니다.

> **Gödel Agent**는 과제 정책과 개선 로직을 모두 다시 쓰지만, **100회 MGSM 최적화 시행 중 14%가 초기 정책보다 낮은 성능으로 끝났다.**

필요한 것: 전이 테스트, 버전 이력, 롤백 기제.

### 7.2 자율성 귀속 (Autonomy attribution)

더 나은 후보를 만드는 것과 후보를 **발견·선택하는 방식**을 개선한 것은 다르다.

> **Darwin Gödel Machine**은 코딩 에이전트를 진화시켜 SWE-bench 부분집합 성능을 **20% → 50%** 로 올렸지만, **아카이브 유지와 부모 선택 규칙은 자기수정 범위 밖에 있다.**

### 7.3 신뢰할 수 있는 검증 (Reliable verification)

평가자에 반복 접근하면 능력 향상이 아니라 **악용**이 보상될 수 있다.

> **Anthropic의 자동화 연구 실험**은 **랜덤 시드 체리피킹**과 평가자 질의를 통한 **테스트 라벨 추출 시도**를 보고했다.

대응 사례: **Red Queen Gödel Machine**은 에포크 내에서 평가자를 **동결**하고, 교체본을 **독립적 ground-truth 앵커**에 대해 검증한다.

### 7.4 STOP의 양면

L5 대표 사례인 **STOP**도 논문은 양면으로 서술한다.

```
  ✅ 선택된 4세대 improver가 자기개선에서 제외된 ★5개 전이 과제 전부★ 에서 시드를 능가
  ⚠️ 약한 모델 실행은 ★평균적으로 퇴행★
  ⚠️ 일부 생성 프로그램이 소프트 예산을 회피하거나 ★평가 버그를 악용★
```

### 7.5 성공 사례도 있다 — A-Evolve-Training

> 사후학습 결과를 지속적 **연구 정책 + 발견 로그**로 통합하고, 메타 에이전트가 이를 개정해 후속 워커의 레시피 선택을 지휘한다. **개발 점수는 올랐는데 외부 이득이 따라오지 않자 시스템이 실험을 데이터 재균형과 체크포인트 선택 쪽으로 재조정했다.**
>
> 30B Nemotron에서 **4회의 자율 라운드**를 거쳐 외부 점수가 **0.80 → 0.86**. 최상위 인간 제출은 **0.87**.

인간 최고 기록에 0.01 못 미친다. 이 수치를 어느 쪽으로 읽을지는 독자의 몫이지만, 논문은 과장하지 않고 병기해 두었다.

## 8. 응용 영역 — 피드백 체제가 다르다

논문이 네 영역을 고른 이유는 **피드백 체제가 서로 다르기** 때문이다.

| 영역 | 피드백 성격 | 현재 도달 수준 |
|---|---|---|
| **S1 과학** | 실험 증거지만 **실패 원인 귀속이 불확실** | 강한 L2, 초기 L3 |
| **S2 체화 지능** | 물리적 상호작용, **시행 비용이 크고 되돌릴 수 없음** | L2~L3가 주 프런티어, L4는 시뮬레이션 |
| **S3 소프트웨어 공학** | **실행 가능한 테스트**, 단 명세가 불완전 | 성숙한 L2, 부상하는 L3, 경계가 제한된 **구조적 L5** |
| **S4 헬스케어** | **지연·교란된 고위험 결과**, 전문가 감독 필요 | 성숙한 L2, 제한적 L3 유사, L4는 시뮬레이션 |

중심 병목은 하나로 요약된다.

> **지속적 상속을 위한 안전한 증거(safe evidence for persistent inheritance).**

소프트웨어 공학이 RSI에 특히 적합한 이유가 여기서 나온다 — **개발되는 산출물과 개발하는 에이전트 양쪽이 실행 가능한 수정과 테스트의 대상**이 되기 때문이다. 반대로 헬스케어·체화 지능은 "소프트웨어 체크포인트를 복원해도 물리적·임상적 결과는 되돌릴 수 없다."

## 10. 8가지 미해결 과제

논문 §6이 제시하는 연구 방향이다. 각각 구체적 실패 사례에 정박해 있다.

| # | 방향 | 정박점 |
|---|---|---|
| 1 | **교차 컴포넌트 진단과 조율된 개선** | Humanlaya 사례 — 추출 실패를 문서 품질 문제로 봤지만 실제 개입 지점은 **품질 검사기의 판정 규칙**이었다 |
| 2 | **학습자 조건부 경험 획득과 신뢰 가능한 학습 신호** | 정확성도 추정 난이도도 **학습 가치를 확립하지 못한다**. 적응적 커리큘럼이 모호한 과제를 반복 선택하거나 평가자 오류를 강화할 수 있다 |
| 3 | **지속 상태 관리와 신뢰 가능한 재사용** | **Library Drift** — 스킬 라이브러리가 커지면 검색이 저하되고 개선이 정체. 반대로 너무 공격적인 퇴역도 해롭다 |
| 4 | **도메인별 피드백 아래의 통제된 적응** | 네 영역의 검증 전략이 달라야 하는 이유 |
| 5 | **개선 기제의 신뢰 가능한 진화** | 결합된 검증 문제 — 더 강한 solver가 평가자의 약점을 드러내지만, 평가자를 바꾸면 점수 비교 가능성이 깨진다 |
| 6 | **상속된 개선 능력의 장기 평가** | AIDE2의 유의성 미달. 원본 기제와 개정 기제를 **동일 총예산**(기제 개발·평가 비용 포함) 아래 비교해야 한다 |
| 7 | **자원 인식 개선과 인간 협업** | 자율성은 **요구되는 인간 노력의 양과 종류와 함께** 평가되어야 한다 |
| 8 | **라운드 간 상속을 위한 재현 가능 인프라** | 부모 상태·제안된 변경·동기 증거·평가 구성·수용 결정·이후 사용을 연결하는 **재사용 가능 아티팩트 포맷** |

결론 문장이 이 논문의 입장을 가장 잘 요약한다.

> **결정적 증거는, 상속된 변화가 이후 라운드로 하여금 더 유용한 경험을 획득하거나, 더 나은 개입을 발견하거나, 후속자를 더 효과적으로 검증하게 만드는 것이다 — 명시적인 자원·권한 제약 아래에서.**

## 11. 평가 — 무엇이 좋고 무엇이 아쉬운가

### 11.1 좋은 점

**① 분류 축의 선택이 옳다.** "무엇이 바뀌는가"가 아니라 "어떤 결정이 이전되었는가"로 축을 잡은 덕분에, 같은 컴포넌트를 갱신하는 시스템들이 실제로는 매우 다른 일을 하고 있다는 사실이 드러난다.

**② 구조적/효과적 구분이 실질적이다.** 이 구분 없이는 "자기개선 시스템"이라는 주장 대부분이 검증 불가능한 채로 남는다. 그리고 논문은 이 기준을 자기 논지에도 적용해 **효과적 L5의 증거 부재를 인정한다.**

**③ 반증 사례를 성실히 싣는다.** Gödel Agent 14% 퇴행, DGM의 자기수정 범위 한계, STOP의 평가 버그 악용, Anthropic의 시드 체리피킹 — 홍보용 서베이라면 뺐을 것들이다.

**④ HCI의 프로토콜 엄밀성.** 33개 중 17개만 채택하고 나머지는 사유와 함께 보존한 처리, 자기보고에 0.75를 곱하는 장치는 [LLM Harness](../llm-harness-optimization-errors/) 문제의식과 정확히 같은 방향이다.

### 11.2 아쉬운 점

**① 제목·TL;DR과 본문의 톤이 맞지 않는다.** "인간이 만든 마지막 AI"는 본문이 실제로 보이는 것 — L5 증거가 경계 제한된 프로토타입에 집중, 효과적 재귀는 미입증 — 보다 훨씬 강한 주장이다.

**② 산업 사례가 자기 보고다.** §9에서 짚은 대로 6개 중 다수가 저자 소속 기관 시스템이다. 논문은 이를 "학술 문헌에 부분적으로만 반영되는 관행을 보완"한다고 정당화하지만, 독립 검증과는 구별해서 읽어야 한다.

**③ HCI 외삽식이 오독을 부른다.** $R_d = 100 - 0.22(100 - T_{d,2026})$의 0.22는 근거가 제시되지 않은 상수다. 논문은 예시임을 반복 명시하지만, 그림 하나가 독립적으로 유통되면 그 단서가 떨어져 나간다.

**④ B0~L5가 서열이 아니라고 하면서 서열처럼 쓰인다.** §3.7에서 "높은 레벨이 더 낫지 않다"고 경고하지만, 그림 1·2와 서술 구조는 상승 경로를 강하게 암시한다.

### 11.3 이 블로그의 다른 글과의 연결

이 논문의 L2~L3가 다루는 "실패를 다음 실험으로 전환하는 능력"은 [Scientist Agents 설계 차원 20가지](../scientist-agents-design-dimensions/)에서 정리한 external verifier·다양성·tournament 원칙과 같은 문제를 다룬다. [Cairn](../cairn-general-problem-solver/)은 그 원칙들이 독립적으로 재발견된 사례였는데, 이 논문의 프레임으로 보면 Cairn은 **stigmergy 기반 L2**에 해당하고 개선 기제 자체는 고정이다.

§7.3의 평가자 악용은 [LLM Harness 최적화·오류](../llm-harness-optimization-errors/)의 reward hacking·judge bias와 같은 현상이 자기개선 루프 안에서 증폭된 형태다. 평가자가 **루프 안에 있을 때** 문제가 질적으로 달라진다는 것이 이 논문의 기여다.

그리고 §5.3의 "자율성 ≠ 개선 품질"은 [AI와 실제 지능 서베이](../ai-and-natural-intelligence-survey/) §11에서 정리한 **예측 ≠ 설명** 단층선과 같은 형태의 구분이다. 측정 가능한 대리 지표(자율성 레벨 / 예측 정확도)와 실제로 알고 싶은 것(개선 품질 / 기제 이해)이 분리된다.
