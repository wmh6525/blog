## 1. 문제: 기존 파인튜닝은 RAG에 맞지 않는다

### 표준 SFT의 문제

```
학습: 질의 → 정답
추론: 질의 + [검색된 문서] → 정답
```

학습할 때는 문서를 **한 번도 보지 못했는데**, 추론할 때 갑자기 문서가 프롬프트에 삽입된다. 모델은:

1. 검색된 문서에서 **관련 정보를 추출**하는 법을 모른다
2. **무관한 문서를 무시**하는 법을 모른다
3. 문서를 근거로 **추론**하는 법을 모른다

### DSF + RAG는 오히려 악화되기도 한다

| 방법 | TensorFlow Hub |
|------|---------------|
| DSF (파인튜닝만) | 86.56% |
| DSF + RAG | **60.29%** (↓26.27%!) |

도메인 파인튜닝된 모델에 RAG를 붙이면 **성능이 오히려 떨어지는** 역설적 현상이 발생한다.

---

## 2. RAFT의 핵심 비유: 오픈북 시험 준비

| 비유 | 접근법 | 문제 |
|------|--------|------|
| **안 보고 시험** | 파인튜닝만 (DSF) | 시험장에서 책을 줘도 활용 못함 |
| **벼락치기 오픈북** | RAG만 (검색 의존) | 교재를 공부 안 하고 시험장에서 처음 봄 |
| **제대로 된 오픈북 준비** | **RAFT** | 교재로 공부 + 참고하면서 답 쓰는 연습 |

RAFT는 학생이 **교재를 미리 공부하고, 시험에서 교재를 참고하면서 답을 쓰는 연습**까지 하는 것과 같다.

## 3. 학습 데이터 구성법

### 핵심 공식

주어진 데이터:
- $Q$: 질의
- $D^{\ast}$: 정답 문서 (oracle) — 답이 포함된 문서
- $D_1, D_2, \ldots, D_k$: 방해 문서 (distractor) — 답과 무관한 문서
- $A^{\ast}$: Chain-of-Thought 정답

**학습 데이터의 $P$%**:

$$Q + D^{\ast} + D_1 + D_2 + \cdots + D_{k-1} \to A^{\ast}$$

정답 문서가 **포함된** 상태에서 방해 문서와 섞어 학습.

**학습 데이터의 $(1-P)$%**:

$$Q + D_1 + D_2 + \cdots + D_k \to A^{\ast}$$

정답 문서가 **없는** 상태에서 방해 문서만으로 학습.

### 왜 (1-P)%에서 정답 문서를 빼는가?

정답 문서를 **항상** 주면 ($P = 100\%$), 모델이 "어딘가에 답이 있겠지"라고만 학습한다. 때때로 정답 문서를 빼면:

- 도메인 지식을 **기억(memorize)**하도록 강제
- 검색이 실패한 상황에서도 답할 수 있는 능력 확보
- 문서 의존도와 기억 의존도의 **균형** 학습

### 구현 세부사항

```python
# raft.py 핵심 로직
oracle = random.uniform(0, 1) < p  # P 확률로 정답 문서 포함
if not oracle:
    docs[0] = random_non_oracle_chunk  # 정답 문서를 방해 문서로 교체
random.shuffle(docs)  # 위치 편향 방지를 위해 셔플
```

**기본 설정**:
- 방해 문서 수: **3개** (+ 정답 문서 1개 = 총 4개)
- 청크 크기: **512 토큰**
- 청크당 질의 수: **5개**
- 질의/CoT 답변 생성: **GPT-4**

## 4. Chain-of-Thought 답변 형식

RAFT의 답변은 단순한 정답이 아니라, **문서 인용이 포함된 추론 과정**이다:

```
##Reason: 
문서에 따르면 ##begin_quote## The Oberoi family is an Indian 
family that is famous for its involvement in hotels, namely 
through The Oberoi Group. ##end_quote## 
Oberoi 가족은 호텔로 유명하며, 
##begin_quote## The Oberoi Group is a hotel company with its 
head office in Delhi. ##end_quote## 
Oberoi 그룹의 본사는 델리에 있다.
따라서 Oberoi 가족은 본사가 델리에 있는 호텔 회사의 일원이다.

##Answer: Delhi
```

**`##begin_quote##` / `##end_quote##`**: 문서에서 직접 인용한 부분을 명시. 이 마커 밖의 텍스트는 모델의 추론.

### CoT의 효과

| 구성 | HotpotQA | HuggingFace |
|------|---------|-------------|
| RAFT (CoT 없이) | 25.62 | 59.07 |
| **RAFT (CoT 포함)** | **35.28 (+9.66)** | **74.00 (+14.93)** |

CoT가 **14.93%p** 개선을 가져온 경우도 있다. 단순 답변은 빠르게 과적합되지만, CoT는 "모델의 이해를 풍부하게" 만든다.

## 5. 5가지 학습 설정 비교

| 설정 | 학습 | 추론 | 설명 |
|------|------|------|------|
| **LLaMA2-7B** | 인스트럭션 튜닝 | 0-shot | 베이스라인 |
| **LLaMA2 + RAG** | 인스트럭션 튜닝 | + 검색 문서 | 검색 추가, 도메인 학습 없음 |
| **DSF** | 도메인 SFT (Q→A) | 0-shot | 도메인 학습, 문서 읽기 훈련 없음 |
| **DSF + RAG** | 도메인 SFT (Q→A) | + 검색 문서 | 도메인 학습 + 검색, but 문서 읽기 미학습 |
| **RAFT** | Q + D\* + D\_k → A\* | + 검색 문서 | **문서 읽기/필터링까지 학습** |

## 6. 실험 결과

### 6.1 주요 벤치마크

| 모델 | PubMed | HotPot | HuggingFace | Torch Hub | TensorFlow |
|------|--------|--------|-------------|-----------|-----------|
| LLaMA2 + RAG | 58.8 | 0.03 | 26.43 | 8.60 | 43.06 |
| DSF | 59.7 | 6.38 | 61.06 | 84.94 | 86.56 |
| DSF + RAG | 71.6 | 4.41 | 42.59 | 82.80 | 60.29 |
| GPT-3.5 + RAG | 71.60 | **41.50** | 29.08 | 60.21 | 65.59 |
| **RAFT** | **73.30** | 35.28 | **74.00** | **84.95** | **86.86** |

**RAFT가 GPT-3.5+RAG를 능가하는 벤치마크**: PubMed, HuggingFace (+44.92!), Torch Hub (+24.74), TensorFlow (+21.27)

GPT-3.5+RAG가 이기는 곳은 **HotpotQA**(일반 지식 멀티홉)뿐 — 도메인 특화가 아닌 범용 추론 과제.

### 6.2 RAFT vs LLaMA2+RAG 개선폭

| 벤치마크 | 개선폭 |
|---------|-------|
| PubMed | +14.5%p |
| HotpotQA | +35.25%p |
| HuggingFace | +47.57%p |
| Torch Hub | +76.35%p |
| TensorFlow | +43.80%p |

### 6.3 DSF+RAG의 역설

| 벤치마크 | DSF | DSF + RAG | 변화 |
|---------|-----|---------|------|
| HotpotQA | 6.38 | 4.41 | **-1.97** (악화) |
| Torch Hub | 84.94 | 82.80 | **-2.14** (악화) |
| TensorFlow | 86.56 | 60.29 | **-26.27** (대폭 악화) |

문서 읽기를 학습하지 않은 모델에 RAG를 붙이면 **방해만 된다**.

## 7. Ablation Study

### 7.1 P% 비율 (정답 문서 포함 확률)

| P% | Natural Questions | HotpotQA |
|----|------------------|---------|
| 0% (정답 문서 없음) | ~0.15 | ~0.35 |
| 40% | ~0.35 | ~0.50 |
| **60%** | ~0.40 | **~0.58** |
| 80% | ~0.38 | ~0.52 |
| 100% (항상 포함) | ~0.25 | ~0.40 |

**P = 100%가 최적이 아니다!** 정답 문서를 항상 주면 모델이 "검색 결과에 답이 항상 있다"고 과적합. **P = 60-80%**가 최적.

### 7.2 방해 문서 수

| 설정 | Natural Questions |
|------|------------------|
| D\* only (0개) | ~0.22 (최악) |
| D\* + 1D | ~0.28 |
| D\* + 2D | ~0.30 |
| **D\* + 3-4D** | **~0.32 (최적)** |

방해 문서 없이 정답 문서만 학습하면 **최악의 성능**. 방해 문서가 있어야 "무관한 문서를 무시하는 능력"을 학습한다.

### 7.3 추론 시 검색 문서 수 (top-k)

방해 문서와 함께 학습한 모델은 추론 시 top-k가 변해도 **안정적인 성능**을 유지. 정답 문서만으로 학습한 모델은 top-k에 따라 성능이 크게 흔들린다.

## 8. 정성적 분석 — DSF vs RAFT

### 질의: "Evolution의 각본가 중 Nicolas Cage와 Tea Leoni 출연 영화의 각본가는?"

**DSF 답변**: "The Family Man" ❌ (영화 제목을 답함 — 사람 이름이 아님)

**RAFT 답변**: "David Weissman" ✅ (문서에서 정확한 인물을 추출)

DSF는 문서에서 **무엇을 추출해야 하는지** 모른다. RAFT는 문서 읽기를 학습했으므로 올바른 정보를 추출한다.

## 10. 파이프라인 전체 흐름

```
=== 오프라인: 학습 데이터 생성 ===

도메인 문서 → 청킹 (512 토큰)
                ↓
         각 청크에서 GPT-4로 질의 5개 생성
                ↓
         각 질의에 대해:
           P% 확률 → 정답 청크 + 방해 청크 3개
           (1-P)% 확률 → 방해 청크 4개
                ↓
         GPT-4로 CoT 답변 생성 (##begin_quote## 포함)
                ↓
         학습 데이터셋 완성

=== 오프라인: 모델 학습 ===

LLaMA2-7B-chat + QLoRA → RAFT 모델

=== 온라인: 추론 ===

질의 → 검색기 (top-k 문서) → RAFT 모델 → 인용 포함 답변
```

## 11. 실무 적용 시 고려사항

### 매뉴얼 RAG 챗봇에 RAFT 적용한다면

```
1. 매뉴얼 PDF → 청킹 (512 토큰)
2. GPT-4로 각 청크에서 Q&A 쌍 생성
3. 정답 청크 + 다른 매뉴얼 청크(방해) 조합
4. CoT 답변 생성 ("매뉴얼 3.2절에 따르면 ##begin_quote##...##end_quote##")
5. QLoRA로 파인튜닝 (단일 24GB GPU 가능)
6. 검색기 + RAFT 모델 배포
```

**비용 추정**: GPT-4 API 비용 (데이터 생성) + 학습 GPU 비용 (A100 수 시간). 문서 수백 페이지 규모라면 $50-200 수준.

## 12. 한계

1. **LLaMA2-7B만 테스트**: 13B, 70B, 다른 모델 패밀리 미검증
2. **이진 QA 개선 미미**: PubMed (Yes/No) 같은 과제에서는 +1.7%p만 개선
3. **HotpotQA에서 GPT-3.5 미달**: 범용 멀티홉 추론은 여전히 대형 모델이 우세
4. **P% 데이터셋별 튜닝**: 최적 $P$가 40-80%로 변동 — 데이터별 실험 필요
5. **GPT-4 의존**: 학습 데이터 생성에 GPT-4 API 비용 발생
6. **4K 컨텍스트 제한**: LLaMA2의 4K 윈도우로 포함 가능한 문서 수 제한
7. **수학적 분석 부재**: 왜 DSF+RAG가 악화되는지에 대한 이론적 분석 없음
8. **단일 검색기**: Contriever만 테스트, 다른 검색기와의 상호작용 미검증

## 13. RAFT의 위치: RAG 최적화 계보에서

```
프롬프트 엔지니어링 (비용 0)
  ↓
임베딩 모델 파인튜닝 (검색 품질↑)
  ↓
★ RAFT (문서 읽기/필터링 학습) ← 여기
  ↓
DPO (충실도 선호 학습)
  ↓
Self-RAG (검색 시점 판단까지 학습)
  ↓
Continued Pre-training (도메인 사전학습)
```

RAFT는 **"LLM이 검색된 문서를 제대로 활용하도록"** 학습시키는, 가장 직접적이고 실용적인 접근법이다.
